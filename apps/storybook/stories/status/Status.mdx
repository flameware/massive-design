# 상태

컴포넌트가 자기에 대해 선언하는 것은 `category`·`status`·`since` 셋뿐이다. 이 표는 그것을 그대로 읽는다 — 손으로 갱신하는 목록이 아니다.

- `planned` — 이번 Phase의 대상이지만 아직 코드가 없다.
- `preview` — 나갔지만 모양이 바뀔 수 있다. 소비처는 쓰되 minor 업그레이드에서 손볼 각오를 한다.
- `stable` — 깨는 변경은 major에서만 난다.
- `deprecated` — 대체가 있다. 새로 쓰지 않는다.

<StatusTable />

표는 **스토리가 있는 것**만 싣는다 — 카탈로그가 스토리 파일을 훑어 만들어지기 때문이다. 그래서 `planned`는 자리를 잡아 두는 스토리를 세우기 전까지 여기 나타나지 않는다. 무엇이 계획돼 있는지는 표가 아니라 [Phase 1 스펙(#275)](https://github.com/flameware/massive-design/issues/275)이 말한다.

## 선언하는 자리

```tsx
const meta = {
  title: "Actions/Button",
  component: Button,
  parameters: { ds: { status: "preview", since: "0.1.0" } },
} satisfies Meta<typeof Button> & ComponentMeta
```

분류와 이름은 `title`이 진다 — 사본을 하나 더 두지 않는다. 사이드바가 묶는 문자열과 이 표가 읽는 문자열이 같으므로 둘이 어긋날 수 없고, 첫 마디가 열 개 분류 중 하나인지는 `satisfies`가 컴파일 시점에 문다.
