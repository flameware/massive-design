손잡이를 끌어서 값을 고르는 폼 컨트롤이에요. 브라우저의
`<input type="range">`에 해당해요.

## 사용법

`Slider.Root` 아래에 `Control`, `Track`, `Indicator`, `Thumb`을 조립해요.

### 값 하나와 범위

`value`나 `defaultValue`에 숫자 하나를 주면 값 하나를 고르고, 배열을 주면
손잡이가 여럿인 범위 슬라이더가 돼요. 조립은 둘 다 같아요. 범위일 때는 각
`Slider.Thumb`에 `index`와 `getAriaLabel`을 줘서 손잡이마다 이름을 붙여
주세요.

### 상태

<Canvas of={SliderStories.States} />

보이는 손잡이 지름은 16px예요. 누를 수 있는 영역은 24×24까지 자동으로
넓어지니 크기를 따로 키우지 않아도 돼요.

### Field·Form과 함께 쓰기

`Field.Root` 안에 두면 라벨, 설명, 오류가 그대로 연결돼요. 제출할 때 값도
자동으로 담기니 따로 연결할 것은 없어요.

## 키보드

Tab으로 손잡이에 닿아요. ArrowLeft와 ArrowRight(또는 ArrowUp과 ArrowDown)가
`step`만큼 값을 바꾸고, Home과 End가 양 끝으로 보내요. 범위일 때는 이웃
손잡이 직전까지만 가요. PageUp과 PageDown은 `largeStep`만큼 옮겨요. 아래
스토리가 이 동작을 선언하고, 테스트가 매번 실제로 눌러서 확인해요.

## 배경

Base UI `Slider.Root`, `Control`, `Track`, `Indicator`, `Thumb` 위에 색과
치수만 입혔어요. 채워지지 않은 트랙은 뜻을 전하지 않으므로 대비 요구가 없어서
Progress의 트랙과 같은 `bg.neutral.soft`를 써요. 손잡이는 잡는 대상 자체가
뜻을 전하므로 아래 배경과 3:1 이상 대비가 나도록 `bg.neutral.solid`를 써요.
화면에 착지할 곳을 정하지 않고 이 컴포넌트를 만든 근거는
[ADR-0026](https://github.com/flameware/massive-design/blob/main/docs/adr/0026-baseline-form-controls-need-no-consumer-evidence.md)에,
보이는 크기를 그대로 두고 누를 수 있는 영역만 넓히는 방식은
[ADR-0020](https://github.com/flameware/massive-design/blob/main/docs/adr/0020-pointer-target-size-is-borne-by-the-hit-area.md)에
있어요.
