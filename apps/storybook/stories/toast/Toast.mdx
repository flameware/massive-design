성공·실패를 알리는 짧은 알림. Base UI의 `Toast` 뒤에 있다 — `role`·라이브 영역·Esc 닫기·초점 관리를 전부 Base UI가 낸다.

## 왜 있는가 (#371)

앱은 저장·삭제가 성공하면 다이얼로그가 조용히 닫힐 뿐이었다. 유일한 손조립은 `data-management-modal.tsx`의 `setClearStatus('모든 데이터가 삭제되었습니다.')` 하나이고, 그 밖의 저장·삭제 성공 경로(`edit-transaction-dialog.tsx`, `add-transaction-dialog.tsx`, `change-password-dialog.tsx`)는 아무 확인도 남기지 않는다. **자리는 실측 1이지만 결손은 화면 전체에 있다** — 착지는 [#377](https://github.com/flameware/massive-design/issues/377)이 이 넷을 한 번에 진다.

## Base UI가 맞는가

맞는다(#325의 Progress, #328의 NumberField가 한 것과 같은 확인). 앱이 필요한 것은 "성공했다"·"실패했다" 한 번 알리는 것뿐이고, `useToast().add({ title, tone })` 하나로 충분하다. Base UI가 스스로 내는 것:

- **역할과 라이브 영역** — `Toast.Viewport`가 `role="region" aria-live="polite"`, 각 토스트가 `role="dialog"`(우선순위 `"high"`면 `"alertdialog"` + 별도 assertive 알림 노드).
- **Esc 닫기** — 토스트 안에 초점이 있을 때 Escape를 누르면 스스로 닫힌다.
- **알림이 포커스를 훔치지 않음** — 뜨는 순간 아무 데도 초점을 옮기지 않는다. Tab(또는 F6)으로 들어가야 옮겨가고, 나가거나 닫으면 직전 자리로 돌아온다.
- **옵셔널 파트** — `title`·`description`이 없으면 `Toast.Title`·`Toast.Description`이 스스로 마운트하지 않는다(빈 태그도, 잘못된 `aria-describedby`도 없다).

DS가 얹은 것은 **톤·면·간격·위치**뿐이다(아래).

## API

```tsx
// 앱 트리 상단 한 번
<Toast.Provider>
  <App />
  <Toast.Viewport />
</Toast.Provider>

// 어디서든
const toast = useToast()
toast.add({ title: "저장됐습니다", tone: "success" })
```

`Toast.Provider`는 Base UI `Toast.Provider`를 그대로 재수출한다 — DS가 더한 것이 없다. `Toast.Viewport`는 닫힌 조립이다: 소비처가 낱개 파트(`Root`·`Title`·`Description`·`Close`·`Action`)를 직접 조립하지 않는다 — `useToastManager()`가 낸 목록을 읽어 톤에 맞춰 그리는 것까지 이 컴포넌트가 진다(ConfirmDialog와 같은 자리: 프리셋이 조립을 대신하되, Base UI의 낱개 파트로 돌아갈 길을 굳이 다시 열지 않는다 — 필요해지면 그 실측이 새 티켓을 연다). `useToast()`는 Base UI `useToastManager()`의 얇은 래퍼로, `add()`에서만 `type`을 `tone`으로 받는다 — `close`·`update`·`promise`는 이번 티켓이 실측한 자리(새 토스트를 띄우는 것)를 벗어나므로 Base UI의 원래 이름을 그대로 쓴다.

## 톤

값 이름은 `Badge`·`Alert`와 같은 이름 공간이다(ADR-0008): `neutral`(기본)·`success`·`danger`. `warning`은 열지 않았다 — 이 티켓이 지명한 자리(저장·삭제 성공/실패, 비밀번호 변경 성공) 중 "주의"에 해당하는 자리가 없다(실측 수요 0).

<Canvas of={ToastStories.Tones} />

색은 대비 게이트가 이미 검증한 조합만 쓴다: `fg.default`는 `bg.neutral.soft`, `fg.{danger,success}`는 각자의 `bg.{family}.soft` 위(Badge와 같은 TEXT_PAIRS). `success`·`neutral` 둘 다 테두리 토큰이 없어(semantic/color.json에 `border.danger`만 있다) `border-default`를 쓴다 — Alert의 `warning` 톤과 같은 자리다.

## 위치와 쌓임

뷰포트는 화면 우하단에 고정한다(모바일은 좌우 여백만 두고 폭 전체). Base UI가 내놓는 `--toast-index`·`--toast-offset-y`·`--toast-height` CSS 변수는 포개진 카드가 뒤로 갈수록 작아지는 "미리보기 스택" 연출을 위한 것인데, 이 티켓의 착지 자리(성공/실패 안내 하나)에는 그 연출이 필요 없어 쓰지 않는다 — 평범한 세로 flex로 쌓는다.
