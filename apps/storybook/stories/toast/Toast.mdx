성공했는지 실패했는지를 잠깐 띄웠다 사라지는 알림으로 알려요. 저장이나 삭제를
마친 뒤 확인을 남길 때 써요.

## 언제 쓰는가

- 저장, 삭제, 비밀번호 변경처럼 끝난 동작의 결과를 알릴 때.

## 언제 쓰지 않는가

- 화면에 계속 남아 있어야 하는 안내는
  [Alert](?path=/docs/feedback-alert--docs)를 쓰세요.
- 사용자가 확인이나 취소를 골라야 하면
  [AlertDialog](?path=/docs/overlays-alertdialog--docs)를 쓰세요.

## 사용법

앱 트리 위쪽에 `Toast.Provider`와 `Toast.Viewport`를 한 번 두고, 어디서든
`useToast()`로 알림을 띄워요.

```tsx
// 앱 트리 상단 한 번
<Toast.Provider>
  <App />
  <Toast.Viewport />
</Toast.Provider>

// 어디서든
const toast = useToast()
toast.add({ title: "저장됐습니다", tone: "success" })
```

`Toast.Viewport`가 띄워진 알림 목록을 읽어 톤에 맞춰 그려요. `Root`,
`Title`, `Description`, `Close`, `Action` 같은 낱개 파트를 직접 조립하지
않아요.

## 주의할 점

### `add()`만 `tone`이라는 이름을 써요

`useToast()`가 돌려주는 `close`, `update`, `promise`는 Base UI의 이름과 사용법을
그대로 따라요. `add()`에서만 알림의 종류를 `type` 대신 `tone`으로 받아요. DS의
다른 컴포넌트와 이름을 맞추기 위해서예요.

### 겹쳐 쌓이는 연출은 없어요

알림이 여러 개 뜨면 세로로 나란히 쌓여요. 뒤로 갈수록 작아지는 카드 모양
연출은 제공하지 않아요.

## 키보드

알림이 떠도 포커스를 빼앗지 않아요. Tab이나 F6으로 들어가야 포커스가 옮겨
가고, 빠져나오거나 닫으면 직전 위치로 돌아와요. 알림 안에 포커스가 있을 때
Esc를 누르면 닫혀요.

## 배경

Base UI `Toast` 위에 톤, 면, 간격, 위치만 입혔어요. `role`, 보조기술이 읽는
영역 선언, Esc 닫기, 포커스 관리는 Base UI가 처리해요. `Toast.Provider`는 Base
UI의 것을 그대로 다시 내보내요.

뷰포트는 화면 오른쪽 아래에 고정하고, 모바일에서는 좌우 여백만 두고 폭
전체를 써요.

색은 대비 검사를 이미 통과한 조합만 써요. `success`와 `neutral`은 전용 테두리
색이 없어서 `border-default`를 쓰고, 이는 Alert의 `warning` 톤과 같아요.
