이전과 다음 버튼, 페이지 번호, 현재 페이지 표시를 갖춘 페이지 이동 막대예요.
페이지 상태는 앱이 관리하고, 이 컴포넌트는 그 값을 받아서 그리기만 해요.

## 언제 쓰는가

- 서버나 화면 쪽에 이미 페이지 상태가 있고, 그 위에 이동 버튼만 필요할 때.
  데이터 테이블 아래가 대표적이에요.

## 언제 쓰지 않는가

- 무한 스크롤이나 "더 보기" 버튼에는 쓰지 마세요. `Pagination`은 페이지
  번호를 하나씩 보여주는 것이 목적이에요.

## 사용법

`page`, `pageCount`, `onPageChange` 세 가지를 주면 돼요. `page`는 1부터
시작해요. 페이지 번호와 줄임표를 어떻게 배치할지는 컴포넌트가 스스로
계산하므로 직접 조립할 것이 없어요.

## 첫 페이지와 마지막 페이지

첫 페이지에서는 이전 버튼이, 마지막 페이지에서는 다음 버튼이 `disabled`가
돼요. 범위를 벗어나는 요청은 아예 눌리지 않아요.

## TanStack Table 위에서

DS는 TanStack에 의존하지 않아요. TanStack Table의 페이지 상태를 그대로 넘기면
돼요. `table.getState().pagination.pageIndex`는 0부터 시작하므로 두 곳에서만
숫자를 바꿔 주세요.

```tsx
import { Pagination } from "@flameware/ui/pagination"

<Pagination
  page={table.getState().pagination.pageIndex + 1}
  pageCount={table.getPageCount()}
  onPageChange={(page) => table.setPageIndex(page - 1)}
/>
```

`onPageChange`에서 `table.nextPage()`나 `table.previousPage()`를 따로 부를
필요는 없어요. `setPageIndex`가 그 둘을 모두 해요.

<Canvas of={PaginationStories.OnTanStackTable} />

## 접근성

바깥 `nav`가 접근성 이름을 갖고, 기본값은 "페이지 이동"이에요. `aria-label`로
바꿀 수 있어요. 현재 페이지 버튼에는 `aria-current="page"`가 붙어요. 줄임표는
`aria-hidden`이라 스크린 리더가 읽지 않아요.

## 키보드

버튼이 모두 `Button`이라 키보드 동작은 네이티브 그대로예요. Tab이 이전 →
페이지 번호 → 다음 순서로 닿고, Enter나 Space가 포커스가 놓인 버튼을 눌러요.

## 배경

Base UI에 대응하는 컴포넌트가 없어서 DS가 직접 만든 컴포넌트예요. 이전, 다음,
페이지 번호 버튼이 모두 `Button`이라 24×24 최소 크기와 상태 표현을 다시
만들지 않아요. 최소 크기 규칙은
[ADR-0020](https://github.com/flameware/massive-design/blob/main/docs/adr/0020-pointer-target-size-is-borne-by-the-hit-area.md)에
있어요.
