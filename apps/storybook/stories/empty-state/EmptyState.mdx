"…없습니다" 화면을 한 모양으로 그려요. 아이콘, 제목, 설명, 행동 버튼 네 가지를
하나로 묶어요.

## 언제 쓰는가

- 목록이나 표가 비었을 때 왜 비었는지와 다음에 무엇을 할 수 있는지를 함께
  보여 줄 때. 거래 내역이나 검색 결과가 여기에 해당해요.

## 언제 쓰지 않는가

- 아직 데이터를 기다리는 중이면
  [Skeleton](?path=/docs/feedback-skeleton--docs)을 쓰세요. `EmptyState`는
  요청이 끝났고 결과가 0건인 것을 확인한 뒤에 놓아요.
- 요청이 실패했으면 [Alert](?path=/docs/feedback-alert--docs)를 쓰세요. 비어
  있는 것과 실패한 것은 다른 사실이에요.

### 아이콘

`EmptyState.Icon`은 위치와 색만 정해요. `<Icon icon={Inbox} />` 하나만 넘기면
40px 크기로 그려요. 아이콘에는 이름이 없으니 뜻은 언제나 제목이나 설명에
두세요.

### 행동 버튼

`EmptyState.Action`은 위쪽 간격만 줘요. 안에 넣을 `Button`은 직접 골라서
넘기세요. 누를 수 있는 영역의 최소 크기는 `Button`이 이미 지켜요.

## 주의할 점

### 스크린 리더는 제목과 설명을 이어서 읽어요

`Root`가 `Title`과 `Description`의 id를 `aria-labelledby`, `aria-describedby`로
받아요. 그래서 스크린 리더로 이 블록에 들어오면 제목과 설명이 이어서 읽혀요.

두 파트 중 실제로 넣은 것에만 속성이 붙어요. `Description` 없이 쓰면
`aria-describedby`를 아예 내지 않고, `Title` 없이 쓰면 `aria-labelledby`를 내지
않아요. 그래서 어떤 조합으로 써도 존재하지 않는 id를 가리키지 않아요.

`Root`는 직계 자식만 보고 이를 판정해요. `Title`을 `<div>`나 다른 컴포넌트로
한 번 감싸면 제목이 그려져도 `aria-labelledby`가 붙지 않으니, 파트는 `Root`
바로 아래에 두세요.

## 배경

Base UI에 대응하는 컴포넌트가 없어서 DS가 직접 만든 패턴이에요. `Root`는
`role="group"`을 써서 이름과 설명 계산만 받고, 페이지 랜드마크를 새로 열지
않아요. 넣지 않은 파트의 id를 가리키지 않으려고 `Root`가 `children`을 같은 렌더
안에서 훑어 판정하기 때문에 첫 화면부터 정확해요. `Action`이 `Button`을 직접
불러오지 않는 이유는 `Card.Footer`와 같아요.
