`Field`들을 묶는 `<form>`. 제출과 서버 오류 표시를 맡는다.

## 언제 쓰는가

- 로그인·회원가입처럼 여러 `Field`를 모아 한 번에 제출하는 자리.
- 서버가 필드별 오류를 돌려주고, 그것을 해당 필드 아래 보여줘야 하는 자리.

## 언제 쓰지 않는가

- 제출이 없는 필터·검색창처럼 "묶기"만 필요하면 `<div>`로 충분하다 — `Form`은 제출·검증 결선이 있다.
- 폼 라이브러리(RHF·TanStack Form)의 결합은 `Field`의 몫이다(Field 문서 참고) — `Form`은 그 라이브러리를 모른다.

## 조립

```tsx
import { Button } from "@flameware/ui/button"
import { Field } from "@flameware/ui/field"
import { Form } from "@flameware/ui/form"
import { Input } from "@flameware/ui/input"

<Form onFormSubmit={(values) => save(values)}>
  <Field.Root name="title" required>
    <Field.Label>제목</Field.Label>
    <Input />
    <Field.Error match="valueMissing">필수 항목입니다</Field.Error>
  </Field.Root>
  <Button type="submit">저장</Button>
</Form>
```

`onFormSubmit`은 필드 이름 → 값의 맵을 직접 받는다 — 네이티브 검증(각 컨트롤의 `required`·`pattern` 등)을 통과했을 때만 불린다. 네이티브 `<form>` 이벤트가 필요하면 `onSubmit`을 대신 쓴다.

## 서버 오류 표시

`errors`는 필드 이름 → 오류 문자열(들)의 맵이다. 같은 이름의 `Field.Root` 아래 `Field.Error`가 — `match`를 주지 않아도 — 그 문자열을 자동으로 보여준다. 필드 자체의 `required`·`pattern` 같은 네이티브 검증과는 다른 경로다: 서버만 알 수 있는 오류(이미 쓰는 이메일 등)를 위한 자리다.
