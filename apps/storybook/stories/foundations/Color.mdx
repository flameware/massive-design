# 색

라이트/다크 전환은 **semantic 계층에서만** 일어난다(`.dark` 클래스 하나). 컴포넌트와 앱은 아래 표의 유틸리티 이름만 쓴다 — palette(`--ds-palette-*`)는 devtools 추적용으로만 남고 `@theme`에 등록되지 않는다.

```css
/* app/globals.css */
@import "@flameware/ui/styles.css";
```

```tsx
<div className="bg-surface text-default border border-default">…</div>
```

라이트/다크는 문서 툴바(위쪽 Theme 스위치)로 바로 확인한다 — 스와치는 지금 열려 있는 모드의 실제 값을 그대로 읽는다.

<ColorTable />

## 역할이 이름 공간이다

같은 `default`·`accent`·`danger`가 `bg`·`text`·`border` 셋에 독립적으로 있다 — `fg.default`와 `border.default`가 우연히 같은 이름이 되는 충돌을 막으려고 역할(`--background-color-*`·`--text-color-*`·`--border-color-*`)이 `--color-*` 하나보다 먼저 해석된다.

## 상태 레이어는 색 유틸리티가 아니다

hover·pressed는 색 토큰이 아니라 `state.layer` 위에 `color-mix`로 얹는 반투명 층이다(`packages/ui/src/state.css`) — 그래서 위 표에는 없다. Button의 상태가 어떻게 그려지는지는 [Actions/Button](/?path=/docs/actions-button--docs)의 "상태" 절을 본다.
