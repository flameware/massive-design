# 자기 패밀리 만들기

DS는 `brand` · `neutral` · `danger` · `success` · `warning` 다섯 패밀리만 갖는다. 손익 색(한국 관행 상승 빨강·하락 파랑) 같은 **도메인 색은 DS가 소유하지 않는다** — 앱마다 다르고, DS가 패밀리를 더할 때마다 쓰지 않는 소비처가 그 무게를 물기 때문이다([ADR-0023](https://github.com/flameware/massive-design/blob/main/docs/adr/0023-second-generation-base-ui.md) §10).

대신 DS 5패밀리를 만든 **같은 램프 생성기를 공개 API로 낸다.** 소비처는 자기 키 컬러 하나로 같은 12단 OKLCH 램프(라이트·다크)를 만들고, 그 CSS 변수를 자기 앱이 소유한다.

## 설치와 호출

```sh
bun add @flameware/tokens
```

```ts
import { createRamp, rampToCssVariables } from "@flameware/tokens/ramp"

const profit = createRamp("profit", { key: "#db2931" }) // 상승 — 빨강
const loss = createRamp("loss", { key: "#0f5fed" }) // 하락 — 파랑

profit.light[8].hex // '#db2931' — 키 컬러가 step 9에 그대로 앉는다
profit.issues // [] — 비어 있으면 lint(규칙군 A) 통과
```

`createRamp`는 DS의 `brand`·`danger`·`success`·`warning`을 만든 것과 **같은 알고리즘·같은 기본 파라미터**를 쓴다. 결과는 `{ name, light, dark, issues }`이고, `light`·`dark`는 각각 12단 `{ step, hex, oklch }` 배열이다.

## CSS로 내보내기

```ts
import { writeFileSync } from "node:fs"

writeFileSync("app/pnl.css", rampToCssVariables(profit) + rampToCssVariables(loss, { prefix: "pnl-down" }))
```

```css
:root {
  --profit-1: #fdfdfc;
  /* … */
  --profit-9: #db2931;
  /* … */
}

.dark {
  --profit-1: #0c0808;
  /* … */
}
```

변수 이름은 `--{prefix}-{step}`이고 `prefix` 기본값은 첫 인자(패밀리 이름)다. `--ds-*` 이름 공간과 겹치지 않는다 — DS가 소유하지 않는 색이라서다. 라이트/다크 전환은 DS와 같은 규약을 쓴다: `:root`가 라이트, `.dark`가 다크다.

## 대비를 스스로 확인하기

DS는 5패밀리를 만들 때 대비 게이트(WCAG 2 AA — 텍스트 4.5:1, 비텍스트 3:1)를 통과시킨다. 공개 API로 만든 램프는 **같은 알고리즘을 쓰지만 게이트를 대신 통과시켜 주지는 않는다** — 키 컬러가 다르면 결과가 다르기 때문이다. 같은 공식으로 소비처가 스스로 잰다:

```ts
import { contrastRatio } from "@flameware/tokens/ramp"

contrastRatio(profit.light[9].hex, "#ffffff") // step 10 텍스트 대 캔버스 — 4.5 이상이어야 한다
```

## 차트 계열색

차트는 DS가 갖지 않지만([ADR-0017](https://github.com/flameware/massive-design/blob/main/docs/adr/0017-dependency-weight-is-a-floor-cost.md) §2), **브랜드에서 계열 둘을 뽑는 단계 규칙과 대비 하한은 있다** — 계열 1은 brand 9(= `bg-accent-solid`), 계열 2는 라이트 brand 7 · 다크 brand 6이다.

```css
:root {
  --chart-1: var(--ds-bg-accent-solid);
  --chart-2: var(--ds-palette-brand-light-7);
}

.dark {
  --chart-2: var(--ds-palette-brand-dark-6);
}
```

하한(계열 ↔ 면 1.5:1 · 계열끼리 1.9:1)과 그 근거, 실측표, 자기 패밀리에서 뽑을 때의 확인 절차는 [`@flameware/tokens` README의 §차트 계열색](https://github.com/flameware/massive-design/blob/main/packages/tokens/README.md#차트-계열색--브랜드에서-둘을-뽑는다)에 있다 — 수가 한 곳에만 살도록 여기서 옮겨 적지 않는다([#334](https://github.com/flameware/massive-design/issues/334)).

## 알아둘 것

- 파라미터(`params`)와 단계별 `overrides`로 곡선을 조정할 수 있다 — DS의 `tokens/ramp.config.json`과 같은 모양이다. `overrides`의 각 항목은 `_why`(근거)가 필수다.
- `createRamp`는 순수 함수다 — 빌드 스크립트에서 한 번 돌려 산출물을 커밋하거나, 런타임에 그대로 불러도 된다.
- `./ramp` 서브패스를 쓰지 않는 소비처는 이 API가 필요로 하는 `culori`를 번들에 물지 않는다.
