# 자기 패밀리 만들기

DS에 없는 색이 필요하면 기준 색 하나로 DS와 같은 방식의 12단계 색
배열(램프)을 직접 만들 수 있어요. 만들어진 CSS 변수는 앱이 소유해요.

DS가 제공하는 색은 `brand`, `neutral`, `danger`, `success`, `warning` 다섯
패밀리예요. 손익 색(한국 관행으로 상승은 빨강, 하락은 파랑)처럼 앱마다 다른
색은 여기에 없어요.

## 사용법

### 1. 패키지 설치

```sh
bun add @flameware/tokens
```

### 2. 램프 만들기

```ts
import { createRamp } from "@flameware/tokens/ramp"

const profit = createRamp("profit", { key: "#db2931" }) // 상승, 빨강
const loss = createRamp("loss", { key: "#0f5fed" }) // 하락, 파랑

profit.light[8].hex // '#db2931' 기준 색이 9단계에 그대로 들어가요
profit.issues // [] 비어 있으면 램프 검사를 통과한 거예요
```

결과는 `{ name, light, dark, issues }`이고, `light`와 `dark`는 각각 12개짜리
`{ step, hex, oklch }` 배열이에요. DS의 `brand`, `danger`, `success`,
`warning`을 만든 것과 같은 알고리즘, 같은 기본값을 써요.

### 3. CSS로 내보내기

```ts
import { writeFileSync } from "node:fs"
import { rampToCssVariables } from "@flameware/tokens/ramp"

writeFileSync("app/pnl.css", rampToCssVariables(profit) + rampToCssVariables(loss, { prefix: "pnl-down" }))
```

```css
:root {
  --profit-1: #fdfdfc;
  /* … */
  --profit-9: #db2931;
  /* … */
}

.dark {
  --profit-1: #0c0808;
  /* … */
}
```

변수 이름은 `--{prefix}-{step}`이고, `prefix` 기본값은 첫 인자로 넘긴
이름이에요. `--ds-*` 이름과 겹치지 않아요. 라이트와 다크는 DS와 같은 규약을
써서 `:root`가 라이트, `.dark`가 다크예요.

## 차트 계열색

DS는 차트 컴포넌트를 제공하지 않지만, 브랜드 색에서 계열 둘을 뽑는 단계
규칙은 있어요. 계열 1은 brand 9단계(`bg-accent-solid`와 같은 색), 계열 2는
라이트에서 brand 7단계, 다크에서 brand 6단계예요.

```css
:root {
  --chart-1: var(--ds-bg-accent-solid);
  --chart-2: var(--ds-palette-brand-light-7);
}

.dark {
  --chart-2: var(--ds-palette-brand-dark-6);
}
```

대비 하한(계열과 배경 1.5:1, 계열끼리 1.9:1), 실측표, 자기 패밀리에서 뽑을
때의 확인 절차는
[`@flameware/tokens` README의 차트 계열색 절](https://github.com/flameware/massive-design/blob/main/packages/tokens/README.md#차트-계열색--브랜드에서-둘을-뽑는다)에
있어요.

## 주의할 점

### 대비는 직접 확인해야 해요

DS는 다섯 패밀리를 만들 때 대비 검사(WCAG 2 AA로 텍스트 4.5:1, 텍스트가 아닌
것 3:1)를 통과시켜요. 직접 만든 램프는 같은 알고리즘을 쓰지만 이 검사를 대신
통과시켜 주지는 않아요. 기준 색이 다르면 결과도 다르기 때문이에요. 같은
함수로 직접 재 보세요.

```ts
import { contrastRatio } from "@flameware/tokens/ramp"

contrastRatio(profit.light[9].hex, "#ffffff") // 10단계 글자와 캔버스, 4.5 이상이어야 해요
```

### 곡선을 조정하려면 근거를 적어야 해요

`params`와 단계별 `overrides`로 곡선을 조정할 수 있고, 모양은 DS의
`tokens/ramp.config.json`과 같아요. `overrides`의 각 항목에는 근거를 적는
`_why`가 필수예요.

### 언제 실행해도 돼요

`createRamp`는 순수 함수예요. 빌드 스크립트에서 한 번 돌려 결과를 커밋해도
되고, 런타임에 불러도 돼요. `./ramp` 서브패스를 쓰지 않는 앱은 이 API가
필요로 하는 `culori`를 번들에 담지 않아요.

## 배경

DS가 도메인 색을 직접 갖지 않는 이유는 앱마다 색이 다르고, 패밀리를 더할
때마다 그 색을 쓰지 않는 앱까지 무게를 물기
때문이에요([ADR-0023](https://github.com/flameware/massive-design/blob/main/docs/adr/0023-second-generation-base-ui.md)
§10). 차트를 DS가 갖지 않는 이유는
[ADR-0017](https://github.com/flameware/massive-design/blob/main/docs/adr/0017-dependency-weight-is-a-floor-cost.md)
§2에 있어요.
