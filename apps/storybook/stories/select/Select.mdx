목록에서 하나를 고르는 팝업 컨트롤. Base UI `Select` 위에 색과 치수만 입혔다 —
네임스페이스형 API로 `Select.Root` 뒤 열넷이 anatomy를 이룬다.

## 언제 쓰는가

- 선택지가 5개를 넘어 세그먼트(ToggleGroup)로는 가로 폭이 넘칠 때.
- 선택지를 그룹·구분선으로 나눠 보여줘야 할 때 — `Select.Group`·`Select.GroupLabel`·`Select.Separator`.

## 언제 쓰지 않는가

- **선택지가 2~4개뿐이고 늘 다 보여도 될 때.** ToggleGroup이 한 번의 클릭으로 끝난다.
- **입력하며 걸러야 할 때.** Select는 타이핑 점프(typeahead)만 있고 필터링은 없다 — Combobox(#289)다.

## 키보드

Tab이 트리거에 닿는다. 화살표가 팝업을 열고 항목 사이를 옮기며, `Enter`가
고른 항목을 확정하고 닫는다. `Escape`는 고르지 않고 닫는다. 타이핑하면 그
글자로 시작하는 항목으로 건너뛴다(typeahead). 아래 스토리가 그 계약을
