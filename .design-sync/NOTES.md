# Design-sync notes

## Repo-specific quirks

- **Package is source-distributed, no `dist/` JS build.** `@massive/ui`'s `package.json` has no `"build"` script; `exports["."]` points straight at `./src/index.ts` (TS source), and `dist/` only holds a generated component manifest (`dist/manifest/`), not compiled JS. `cfg.entry` is set to `packages/ui/src/index.ts` and the converter bundles directly from TS source via esbuild.
- **No `.d.ts` anywhere** for the same reason - `findTypesRoot`/`exportedNames()`/`loadDts()` (ts-morph, `lib/dts.mjs`) all assume a built `.d.ts` tree and found zero files, which zeroed out `exportedSet` and silently produced 0 components. Forked as `.design-sync/overrides/dts.mjs` (`libOverrides` entry has the reason): falls back to `package.json`'s `exports["."]` when it points at a `.ts`/`.tsx` file with no `types`/`typings` field, and loads the real `.ts`/`.tsx` source tree into the ts-morph project instead of a `.d.ts` glob when none are found. `[GENERAL]` - this is a generic gap for any source-distributed (shadcn-style) package, not unique to this repo.
- **Storybook story format is non-standard: one shared title, one component per story export.** `apps/storybook/stories/Components.stories.tsx` is *generated* from `@massive/ui`'s manifests (`scripts/generate-component-contracts.mjs`-adjacent tooling) - every component gets one story export (`export const Accordion = story("accordion")` etc.) under a SINGLE title `"Components/Manifest references"`, rendered via a shared `CatalogReference` component that switches on a catalog entry + control selection. The converter's default `titleParts()` derives the component name from the title's last segment, which only ever yields `"Manifestreferences"` here - it can never discover the real per-story component identity from the title. Forked `.design-sync/overrides/source-storybook.mjs` (see file header): title-based grouping is tried first (kept generic for any OTHER story file that follows the normal one-title-per-component convention), and only when that doesn't land on a real package export does it fall back to matching the STORY's own display name against the export set (squash-compare) - which is 1:1 correct here since each story's name IS the component name.
- `CatalogReference.tsx` imports real components directly from `"@massive/ui"` (not indirectly), so the story-import package-redirect (bundle shim) works generically with no `cfg.provider`/`cfg.storyImports` needed.
- `System/Trust and workflow` was the repo's own Figma-sync verification dashboard; removed in the 2026-09 review (Figma is now an on-request snapshot, see `docs/agents/design-system-sync.md`). Nothing to exclude any more.
- **`[FONT_MISSING]`: "Pretendard Variable"/"Pretendard"/"Apple SD Gothic Neo" referenced by `--font-sans` (packages/tokens/dist/tokens.css) but not shipped anywhere in the repo** - no woff2/ttf, no CDN `@font-face`, no data-URI; the repo's own Storybook build renders with the same system-font fallback. Searched: `packages/tokens/dist`, `packages/tokens/scripts`, storybook static output, docs. **User explicitly accepted the fallback stack** (Apple SD Gothic Neo / system sans-serif) rather than sourcing/bundling a real Pretendard font file - this is an intentional, recorded substitute, not an oversight. If a real Pretendard woff2 becomes available later, wire it via `cfg.extraFonts` and re-verify every text-heavy component's previews (font substitution can shift line-height/wrapping).

## Re-sync risks

- The two forks (`source-storybook.mjs`, `dts.mjs`) are load-bearing for component discovery on this repo - if a future Storybook/TS convention change makes them unnecessary (e.g. the DS starts shipping real `.d.ts`, or story files move to one-title-per-component), the fork bodies stop being useful but are otherwise inert (the fallback paths only trigger when the primary heuristic misses) - safe to remove once verified.
- `docs: 0/34 components matched` in the build log - no per-component doc discovery is wired (`cfg.docsDir`/`cfg.docsMap` unset). Every `.prompt.md` was synthesized from `.d.ts` + previews only, not from any hand-written usage docs in this repo. If richer per-component docs exist somewhere and should feed `.prompt.md`, set `cfg.docsDir`.
- Font-fallback acceptance above should be re-confirmed if the DS's `--font-sans` stack changes, or if Pretendard becomes available to bundle.
