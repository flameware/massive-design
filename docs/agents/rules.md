# 규칙 원장

나중 작업을 구속하는 **디자인 시스템의** 규칙. 각 규칙은 원문 그대로이고, 그 규칙을 낳은 맵의 서술은 `../handoff/`의 완료 기록에 있다.

**1세대 표시가 붙은 절과 항목은 역사다.** 계약·매니페스트·`parts`·Figma 파생 채널·radix를 전제한 규칙은 [ADR-0023](../adr/0023-second-generation-base-ui.md)이 대체했고, 그 도구는 #277에서 삭제됐다(태그 `v1-shadcn`). 승계된 것은 축·값 이름 공간, 대비, 포인터 기하, 바닥값, 방법론이다 — 새 코드는 그것만 구속한다. 매니페스트 생성기의 내부 규약은 태그 `v1-shadcn`의 `packages/ui/scripts/manifest/README.md`에 있다.

주제별로 묶었다 — 맵 연대순이 아니다. 무언가를 하기 전에 그것을 구속하는 규칙이 있는지 이 순서로 찾으면 된다.

## 무엇이 컴포넌트가 되는가 *(첫 항목은 1세대 — 파생 채널 전제)*

출처: P1 [#88](https://github.com/flameware/massive-design/issues/88) · P2 [#118](https://github.com/flameware/massive-design/issues/118) — [`../handoff/catalog-maps.md`](../handoff/catalog-maps.md)

- **An item that derived channels cannot tell apart does not get its own component** ([#97](https://github.com/flameware/massive-design/issues/97)). Manifests and Figma carry anatomy and configuration state, not behaviour, so a behaviour-only variant cannot satisfy the "code, Storybook and Figma in one generation" completion definition. This is the rule that ruled Drawer out against Sheet, and it governs P2 triage.
- **A composed component consumes the original rather than copying it** ([#91](https://github.com/flameware/massive-design/issues/91)). Combobox imports Command and Popover; copying would fork their keyboard contracts.
- **A preset replaces the assembly, never hides the parts — and a second one needs the same evidence a first axis needs** ([Phase 2 ConfirmDialog #330](https://github.com/flameware/massive-design/issues/330), [`../handoff/phase-2-base-ui-map.md`](../handoff/phase-2-base-ui-map.md)). `ConfirmDialog` composes `AlertDialog`'s existing parts and adds exactly three things (initial focus on confirm, `tone="danger"` → destructive `Button`, a loading state) — `AlertDialog` loses nothing and stays reachable. The boundary: two or more actions, a rich body, or a different initial focus sends the caller back to `AlertDialog`. A second preset opens only where the same assembly repeats three or more places, not on a hunch.
- **A component that doesn't fit a site's shape means reaching for the DS's other component, not hand-assembling** ([Phase 2 Alert `tone="warning"` adoption #353](https://github.com/flameware/massive-design/issues/353)). `Alert` is block-level and didn't fit three inline sites (a rate-staleness badge, two row/cell status icons); the fix was not to leave them hand-assembled but to reach for `Badge tone="warning"` (already `inline-flex w-fit`) and, where even a pill was too much, the bare `text-warning` token. The structural read ("Alert doesn't fit here") was right the first time this site was looked at — the mistake was stopping there instead of finding the DS's other axis.
- **A determinate-progress component must not be given a faked value — an unknowable wait is a spinner** ([Phase 2 Progress·Pagination·NumberField adoption #355](https://github.com/flameware/massive-design/issues/355)). `Progress` is `role="progressbar"` plus a real value; invest diary's bulk price refresh has no such value (one batched request, `current` jumps straight from 0 to `total`) so it stayed on `Spinner` rather than animate a bar that would move without meaning. CSV/JSON import, which awaits one row at a time and has a real count, got the bar.
- **전체 화면 대기는 자리가 둘이어서 컴포넌트가 되지 않았다 — 이건 기각이 아니라 계수 결과다** ([#361](https://github.com/flameware/massive-design/issues/361), [#351](https://github.com/flameware/massive-design/issues/351)이 연 질문). `Spinner size="xl"`이 착지한 뒤 소비처(invest diary)의 대기 자리를 전부 다시 셌다. `min-h-screen` 가운데 정렬 + `xl` + "로딩중…"이라는 **같은 손조립은 정확히 2자리**(`app/page.tsx`·`app/dashboard/notes/page.tsx`)다 — #351이 셋째로 세었던 `PortfolioChartLWC`는 `h-64`에 문구가 없는 **컨테이너 내부** 대기라 같은 모양이 아니었다. 나머지 대기는 이미 갈려 있다: 내용 모양을 아는 대기는 `Skeleton`(12자리), 글자 곁은 `Spinner` `sm`·`lg`(5자리). 그래서 남은 둘은 컴포넌트가 없어 손조립인 것이 아니라 **라우트 전환 대기라는 자리 자체가 둘뿐**이다. "같은 조립이 세 자리 이상에서 반복될 때만 프리셋을 연다"([#330](https://github.com/flameware/massive-design/issues/330))의 하한에 못 미치므로 `PageLoader`류는 열지 않는다. 셋째 자리가 생기면 같은 방식으로 다시 센다 — 판단이 아니라 수가 이 문을 연다.
- **이름을 주는 것이 규율을 더하는가 시험** ([Phase 3 Stack/Grid 판정 #375](https://github.com/flameware/massive-design/issues/375)·[#376](https://github.com/flameware/massive-design/issues/376), [`../handoff/phase-3-base-ui-map.md`](../handoff/phase-3-base-ui-map.md)). 반복되는 조합(`space-y-4`·`space-y-6`, `flex gap-2 items-center` 등)이 "3자리 이상 반복" 문턱을 수로 넘어도, 그 반복이 이미 토큰 척도(`--spacing`) 안에서만 벌어지고 있으면(임의 값 `gap-[…]` 류 0건) 이름을 여는 것이 소비처에게 강제할 새 제약이 없다 — 이름이 규율을 더하지 못하면 컴포넌트를 열지 않는다. invest diary의 레이아웃 재실측(레이아웃 63·여백 45, 임의 간격 값 0건)이 이 시험을 처음 명시적으로 적용한 사례다.
- **네이티브 HTML 입력에 대응하는 폼 컨트롤은 소비처 근거 없이 만든다** — "소비처가 잣대다"(§10)의 유일한 예외다 ([ADR-0026](../adr/0026-baseline-form-controls-need-no-consumer-evidence.md), [숲마루 온보딩 맵 #396](https://github.com/flameware/massive-design/issues/396), [`../handoff/second-consumer-onboarding-map.md`](../handoff/second-consumer-onboarding-map.md)). 판정 기준은 이름 목록이 아니라 한 문장이다 — **네이티브 HTML 입력에 대응하는가.** 이 기준으로 Switch(`type="checkbox" role="switch"`)·Slider(`type="range"`)·Radio(`type="radio"`)가 착지 자리 없이 열렸다(#399·#400·#401). 오버레이·드러내기·표시 전용 컴포넌트(Popover·Accordion·Meter 등)는 입력이 아니므로 이 예외 밖이고, 여전히 §10대로 소비처 실측을 기다린다. 예외 밖에서는 착지 없는 `preview`가 승격되지 않는다는 규약이 그대로 산다.

## 계약이 무엇을 담는가 *(1세대 — 계약은 meta로 대체됐다, ADR-0023 §6)*

출처: P2 [#118](https://github.com/flameware/massive-design/issues/118) · 파생 채널 [#140](https://github.com/flameware/massive-design/issues/140) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221)

- **`anatomy` names what the consumer assembles** ([#172](https://github.com/flameware/massive-design/issues/172), [ADR-0018](../adr/0018-anatomy-is-the-consumer-assembly.md)). A node the component renders on its own is not anatomy however real it is in the tree. Portal was public on three components and not on four, and the asymmetry was not a gate failing to reach a surface — the three were simply **opened without grounds**, and their export never worked: `Content` wraps its own Portal, so a consumer's `container` was silently ignored. Its corollary is that `breaking` can be *executed* while the package is private, unpublished and unconsumed — and the trigger that closes that path is the **first npm publish**, an event, never a date.
- **A third-party library owns the nodes we do not give a `className` to, and the contract must say so** ([#122](https://github.com/flameware/massive-design/issues/122)). The boundary is class ownership; each externally-owned surface is listed in `externalSurfaces` with its own reason. Ownership reaches further than nodes — it takes inline styles ([#124](https://github.com/flameware/massive-design/issues/124)) and prop name spaces ([#125](https://github.com/flameware/massive-design/issues/125)) too. Its corollary: **we do not re-export a third-party component through our barrel**, because a surface cannot be ours and theirs at once.
- **What derived channels do not carry, the contract declares and a person verifies — and the boundary is the cause** ([#149](https://github.com/flameware/massive-design/issues/149), [#187](https://github.com/flameware/massive-design/issues/187), [ADR-0010](../adr/0010-behaviors-are-declared-and-human-verified.md), [ADR-0015](../adr/0015-behaviors-boundary-is-the-cause.md)). `behaviors` takes interactions whose cause is **not an explicit activation** (hover, drag, long press, a timer, focus arriving, typing at a *closed* control) in three kinds — `control-gesture`, `open-cause`, `implicit-change`. It does not take what the role already requires (arrow movement and highlighting inside an open surface, Escape and outside-press dismissal, click activation, and the defaults hanging off those), nor changes a person did not cause (image load, password-manager detection, container resize). All 51 contracts were surveyed against the sources `bun.lock` pins, so `behaviors: {}` means "confirmed it brings nothing". `bun run sync:checklist` printed the human checklist from the contracts (deleted in #277); a list kept by hand leaked three times.
- **`reference.guidance` speaks to the consumer, never to the next maintainer** ([ADR-0022](../adr/0022-guidance-is-for-the-consumer.md)). `use` and `limits` answer "do I reach for this here" — `limits` must name the alternative, never end on "don't use this". `evidence` records which consumer need opened the component and is maintainer information. A sentence that answers "why did we build it this way" is **rationale, not guidance** — it lives next to the declaration it explains (a source comment) or as an ADR pointer, never as prose inside `limits`. `check` enforces the shape mechanically (length caps: `use` 120, `evidence` 150, `limits` 200; no issue numbers inside `limits`).

## 축과 이름 공간

출처: 표면 층위 공백 [#139](https://github.com/flameware/massive-design/issues/139) · 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221)

- **A new axis's default is the value that preserves published instances** ([#139](https://github.com/flameware/massive-design/issues/139)'s four batches). `knockout: none`, `placement: auto`, `frame: none` (but `icon` for `EmptyMedia`, because that is what it already rendered), `spacing: separate`, `indicator: pill`, `rank: legend` — in every case the default is the value the part already rendered, which is what makes opening an axis `additive` rather than a reinterpretation of instances already published. "The default emits no class" is the wrong gloss: only three of the six emit `""`, while `frame`, `indicator` and `rank` name a shape the part was already drawing.
- **An axis name must not already mean something else in the catalog** ([#125](https://github.com/flameware/massive-design/issues/125), [ADR-0008](../adr/0008-axis-and-value-name-spaces.md)). Upstream's name is the default choice, but only if it is free here — `align` was taken twice over, so the addon axis became `placement`; `variant` already names the root's semantic/emphasis axis, so the media slot became `frame`, the tab marker `indicator`, the field caption's tier `rank`. **The rule outlived the migration to Base UI**: `Table`'s sort axis was specced as `align`, but `Menu.Popup`·`Combobox` already use `align` for Base UI `Positioner`'s "which corner of the trigger the floating surface hangs off" (`menu.tsx:44`·`combobox.tsx:126`) — the same collision ADR-0008 first ruled `align` out for, with the same three-value vocabulary (`start`/`center`/`end`) making the clash worse. The axis opened as `textAlign` instead; only the name moved, not the values or the default ([Phase 3 #367](https://github.com/flameware/massive-design/issues/367), [`../handoff/phase-3-base-ui-map.md`](../handoff/phase-3-base-ui-map.md)). A spec document's name is not exempt from this check just because it predates the axis. **A part-level axis name answers the same test one level down** ([#224](https://github.com/flameware/massive-design/issues/224)): a part introduces `variant` only when its root has none ([ADR-0019](../adr/0019-what-variant-names.md) decision 1 as amended) — `DropdownMenuItem.variant` is the first case; where the root does have `variant`, a part inherits it (`ToggleGroupItem.variant`, [#179](https://github.com/flameware/massive-design/issues/179)). **Value names are the other way round: their name space is the axis, not the catalog** — `chart.indicator`'s `line` and `tabs.indicator`'s `line` mean different pictures. And a value names the state of *what the axis names*, never whether a class is emitted: `frame: none` means no frame, not no class. No gate sees this — it is a meaning judgement.
- **`variant` names how the root itself stands, and a component fills only the dimensions that apply** ([#173](https://github.com/flameware/massive-design/issues/173), [ADR-0019](../adr/0019-what-variant-names.md)). Across the catalog the axis carries three — meaning, emphasis, form — and `Badge` filling only meaning is no more a deviation than `Item` filling only emphasis. Mixing two in one axis is not forbidden either: `Button` already ships `default·destructive·outline·secondary·ghost·link`. The rule that survives is that **adding a dimension needs measured demand**, and whether it arrives on the same axis or a second one is decided by whether the derived channels must multiply the two.
- **An axis a consumer works around is an axis that's short — but the adoption ticket that finds the bypass is not the one that fixes it** ([#351](https://github.com/flameware/massive-design/issues/351), from [Phase 2 Spinner/Separator adoption #332](https://github.com/flameware/massive-design/issues/332)). `Spinner`'s `size` scale (`sm`·`md`·`lg` = 14·16·18px) is inline-only, built for standing next to text; invest diary's three full-page waits needed 32px, and the working fix was `className="size-8"` (harmless, since `cn` is tailwind-merge, but a bypass of the axis). Whether the answer is widening the scale (`xl`) or recognizing the need as a *placement* problem rather than a *size* one is a question for its own issue, not a call the adoption ticket makes on the way past.
- **Subpaths follow Base UI's module split; namespaces group the parts of one module** ([#401](https://github.com/flameware/massive-design/issues/401), [#411](https://github.com/flameware/massive-design/pull/411), [ADR-0023](../adr/0023-second-generation-base-ui.md) §5). Base UI ships `radio` and `radio-group` as separate modules, so `@flameware/ui` ships `./radio` (`Radio`) and `./radio-group` (`RadioGroup`) — the same shape as `./toggle` + `./toggle-group` — rather than inventing a `Radio.Group` Base UI does not have. Parts inside one module (`Slider.Root`·`Slider.Thumb`, `Dialog.Popup`) stay a namespace; a module whose parts the wrapper folds into one element (`Checkbox`, `Radio` folding `Root`+`Indicator`) exports flat. §5's reason for namespaces is 1:1 correspondence with Base UI, and this keeps that correspondence at the module level too. The issue's `Radio.Group` wording was reconsidered after publishing `0.6.0` and kept as shipped.

## 토큰과 대비

출처: P2 [#118](https://github.com/flameware/massive-design/issues/118) · Phase 1 [#275](https://github.com/flameware/massive-design/issues/275) — [`../handoff/phase-1-base-ui-map.md`](../handoff/phase-1-base-ui-map.md)

- **A component with a face paints `--ds-state-base` in one place, never `bg-*`** ([#280](https://github.com/flameware/massive-design/issues/280) + [#299](https://github.com/flameware/massive-design/issues/299), [`../handoff/phase-1-base-ui-map.md`](../handoff/phase-1-base-ui-map.md)). The state layer (`packages/ui/src/state.css`) is the **only writer of `background-color`**: it composes hover·pressed over `--ds-state-base` with `color-mix`, so a `bg-accent-solid` utility emitted at the same specificity later in the sheet wins and hover·pressed silently vanish — that was #299, met in the consuming app, not in any gate. Disabled is `[data-disabled]`. The `@flameware/ui` grep gate (ADR-0023 §12) keeps this.
- **A contrast requirement follows the role, not the token family** ([#109](https://github.com/flameware/massive-design/issues/109)). WCAG 1.4.11 binds "UI components that indicate state", so a *fill* can be inside the non-text gate: a **control affordance** — Scroll Area's thumb, Switch's off track — is the thing you grab, so it owes 3:1 against the surface it sits on and takes `bg.neutral.solid` (alias `neutral-solid`, [ADR-0003](../adr/0003-neutral-solid-alias-name.md)). Its opposite, the **track remainder** (Progress, Slider), owes nothing, because the filled part carries the meaning. Both roles are defined in `CONTEXT.md`. Four places had agreed on neutral 3 by accident, reached through three different paths; two of them were invisible at 1.09:1 and 1.17:1 and passed three gates in silence. `CODE_VERIFIED` is not a disproof of a defect no gate is looking for.
- **이름이 값보다 많은 상태는 선언되어야 한다** ([#337](https://github.com/flameware/massive-design/issues/337)). 값이 같은 semantic 이름을 두는 것은 막지 않는다 — 나중에 갈라야 할 때 이름을 바꾸는 것은 깨는 변경이지만 값 한 줄은 아니다. 막는 것은 **조용한 동일값**이다. 이름이 둘이면 소비처는 역할이 둘이라고 읽고, 둘 사이를 오가는 변경을 무해한 리팩터로 착각한다 — 소비처가 미터의 트랙을 `bg-inset`에서 `bg-subtle`로 "한 단계 내렸다"고 믿었고 그 변경은 아무것도 하지 않았다([investmentdiary#368](https://github.com/flameware/investmentdiary/pull/368)). 그래서 규약이 아니라 게이트가 지킨다: 같은 **계열** 안의 동일값 형제를 토큰이 `$extensions["design.massive.sameValue"]`로 선언하고 `tokens:lint` **B16**이 정확히 일치시킨다(빠지면 소비처가 속고, 남으면 낡은 경고가 남는다). 계열이 다르면 면제다 — `bg.neutral.solid`와 `border.strong`이 둘 다 neutral 9인 것은 정상이고, 소비는 값이 아니라 역할을 따른다.
- **게이트가 재지 않는 쌍은 없는 것과 같다 — 채움 ↔ 면이 그랬다** ([#336](https://github.com/flameware/massive-design/issues/336) → [#337](https://github.com/flameware/massive-design/issues/337)). 대비 게이트는 오래도록 면 위의 **글자**와 면 위의 **테두리**만 봤고, 면 위의 **채움**은 보지 않았다. 그 사이에 `bg-accent-soft`가 `bg-subtle` 위에서 1.00:1이었다 — 면 사다리와 채움 사다리가 팔레트 step 3을 공유하기 때문이고, 세 게이트 전부 초록이었다. 바로 위 항목의 "네 곳이 우연히 neutral 3에 합의했다"와 같은 뿌리다. `*.soft`의 1.00은 그대로 두되(그것이 조용한 틴트의 정의다) **보여야 하는 채움**에 `bg.<family>.muted`를 두고 `fill` 게이트가 5패밀리 × 5면 × 2모드를 잰다. 하한 1.35는 WCAG가 주지 않는 수라 **측정이 근거다** — 소비처가 "안 보인다"고 판정한 1.22와 고친 뒤 1.49 사이에서, 라이트·다크가 함께 넘는 가장 높은 자리다.
- **이미 토큰인 것을 컴포넌트로 재포장하지 않는다** ([Phase 3 Stack/Grid 판정 #375](https://github.com/flameware/massive-design/issues/375), [`../handoff/phase-3-base-ui-map.md`](../handoff/phase-3-base-ui-map.md)). 간격 척도(`--spacing`, `packages/tokens/tokens/primitive/scale.json`)처럼 Tailwind `@theme`가 이미 강제하는 값 집합이 있으면, 그 위에 컴포넌트 이름 하나(`Stack`/`Grid`)를 얹어도 그 컴포넌트가 실제로 하는 일은 이미 동작하는 `flex flex-col gap-4`를 감싸는 것뿐이라 소비처가 새로 지킬 규율이 생기지 않는다. 척도는 이미 토큰의 몫이고, 그 척도를 부모가 자식에게 어떻게 적용하는가(조립)는 소비처의 몫으로 남는다.
- **떠 있으면 `bg-overlay`, 흐름 안이면 `bg-surface` — 그리고 그 면 위 항목의 `--ds-state-base`는 그 면 자신의 색이다** ([#387](https://github.com/flameware/massive-design/issues/387)). 두 문장은 한 규칙의 앞뒤다. 앞은 면 사다리를 가르는 자리다: Dialog·Drawer·Select·Menu·Combobox의 팝업은 문서 흐름 밖에 떠서 `bg-overlay`를 지고, Card·PageShell은 흐름 안이라 `bg-surface`다 — 라이트에서는 같은 값이라 어긋나도 보이지 않고 **다크에서만 갈린다**(surface=neutral-dark-2, overlay=neutral-dark-3). Menu·Combobox가 그래서 조용히 어긋나 있었다. Tooltip은 `bg-inverse`라 규칙 밖이다. 뒤는 그 면 위에서 `.state`가 섞을 바탕이다: `state.css`는 alpha 0%일 때 `--ds-state-base`를 **그대로 칠하므로**, 거기 회색 토큰(`neutral-soft`)을 두면 아무 상태도 아닌 항목이 이미 회색이고 하이라이트 8%는 그 위 8%밖에 못 낸다 — SelectItem·MenuItem이 그 상태로 서 있었다. 팝업 자신의 면색을 주면 쉬는 항목은 보이지 않고 8%는 불투명한 면 위에서 섞인다. 지우고 투명으로 두는 것은 답이 아니다 — base가 없으면 color-mix가 투명 위에서 일어나고 `state.css`가 경고한 @supports 폴백에 걸린다.
- **소비처의 brand 키 오버라이드는 게이트 표를 복사하지 않고 공유하며, 실패는 경고가 아니라 에러다** ([#398](https://github.com/flameware/massive-design/issues/398), [숲마루 온보딩 맵 #396](https://github.com/flameware/massive-design/issues/396), [`../handoff/second-consumer-onboarding-map.md`](../handoff/second-consumer-onboarding-map.md)). `@flameware/tokens/ramp`의 `createBrandOverride(key)`는 키 컬러 하나(step 9 앵커, light/dark 공통)로 `--ds-palette-brand-*`만 덮고, `accent` semantic이 이미 팔레트를 참조하므로 그 계열 전부가 따라온다. 대비 판정은 `scripts/contrast.mjs`의 `TEXT_PAIRS`·`NONTEXT_PAIRS`·`FILL_PAIRS`와 그 게이트값을 `scripts/lib/brand-gate.mjs`가 그대로 import해 brand를 실제로 참조하는 쌍만 프로그램적으로 골라 재사용한다 — 세 쌍만 하드코딩하면 이름은 달라도 같은 값을 참조하는 자리(`border.focus` 등)를 놓친다. 게이트를 못 넘는 키는 어느 쌍이 몇 대 몇으로 떨어졌는지 담아 에러를 던진다(경고 아님). **구조적 약점**: `build.mjs` → `brand-gate.mjs` → `contrast.mjs` → `build.mjs`가 순환 import다 — 세 파일 다 순환 대상을 함수 본문에서만 참조해 지금은 안전하지만, 다음에 이 중 하나를 모듈 최상단 즉시실행 코드로 바꾸면 조용히 깨진다.
- **레퍼런스를 옮길 때 옮기는 것은 철자가 아니라 뜻이다** ([#388](https://github.com/flameware/massive-design/issues/388), [ADR-0025](../adr/0025-reference-words-carry-meaning-not-spelling.md)). shadcn의 토큰 이름과 DS의 semantic 이름은 **어휘가 겹치지만 뜻이 겹치지 않는다** — shadcn의 `--accent`는 브랜드가 아니라 hover용 연회색(DS `bg-subtle`)이고 브랜드는 `--primary`다. `--input`은 면이 아니라 테두리고, `--accent`와 `--muted`는 이름이 다른데 같은 값이다. 옮길 때 물을 것은 "DS에 같은 이름이 있나"가 아니라 **"그 이름이 그 자리에서 무슨 일을 하나"**다. 대조표는 ADR-0025가 갖고 있다(1세대 shim `.design-sync/sb-reference/assets/iframe-Xdyc_jWD.css`를 읽어 고정한 것이다). 뜻을 읽은 뒤 **DS가 다른 값을 고르는 것은 오류가 아니다** — `toggle.tsx:52`의 켜짐이 브랜드 솔리드인 것이 그 경우이고, 근거가 적혀 있지 않으면 다음 대조가 되돌린다.

## 포인터 기하

출처: 터치 대상 크기 [#111](https://github.com/flameware/massive-design/issues/111) — [`../handoff/pointer-target-map.md`](../handoff/pointer-target-map.md) · [ADR-0020](../adr/0020-pointer-target-size-is-borne-by-the-hit-area.md)

- **The floor is WCAG 2.5.8 (AA) 24×24 CSS px, borne by the hit area; the visual dimension does not move** (ADR-0020 decisions 1·2). AAA 44 is consumer advice in `CONTEXT.md`, never contract — its spacing exception is a condition the consumer's layout creates. The rule binds every pointer unconditionally: no `pointer: coarse` branch, because derived channels cannot tell the two apart (decision 3).
- **The mechanism is a transparent `after:` (or `before:` where `after:` already draws) pseudo-element, expanded centre-symmetrically to 24, and it stands aside for externally owned surfaces** (decision 4, [#230](https://github.com/flameware/massive-design/issues/230), [#249](https://github.com/flameware/massive-design/issues/249)). Overlap with a neighbour is **declared, not solved** — the gate computes the excess, no contract field carries it, and the consumer judges (decision 5). Two traps the instrument caught: an absolute pseudo-element's containing block is the padding box, and widening one axis without `inset-*-0` on the other collapses it to zero.
- **`after`·`before` stay `ignore:` in the policy table, and the floor is measured by a separate tool** (decision 6, [#232](https://github.com/flameware/massive-design/issues/232)). *1세대의 문장은 여기까지다*: the gate diffed rendered hit areas against the committed baseline; a place the rule cannot reach was a named row in `docs/research/pointer-target-exceptions.json` with its reason, never a widened `ignore:`; and it was not on CI, because promotion waited on a regression reproducing across generations. **2세대는 셋 다 뒤집었다** (#279): `bun run pointer-gate`는 #277에서 삭제됐고, `apps/storybook/test/stories.test.mjs`가 같은 하한을 같은 계기(`elementFromPoint`로 재는 실효 히트 영역)로 잰다. 모집단은 매니페스트의 축 곱이 아니라 **스토리**이고, 기준선 TSV도 예외 목록도 없으며(하한 미달은 커밋되기 전에 고친다), CI에 있다. 살아남은 것은 규칙 자체다 — 하한은 히트 영역이 지고 시각 치수는 움직이지 않는다.
- **포인터 계기의 면제는 특정 컴포넌트가 아니라 일반 패턴으로, self-test와 함께 추가한다** ([Slider #400](https://github.com/flameware/massive-design/issues/400), [`../handoff/second-consumer-onboarding-map.md`](../handoff/second-consumer-onboarding-map.md)). Base UI Slider의 네이티브 `<input type="range">`는 `clip-path:inset(50%)`로 히트 테스트에서 빠져 `elementFromPoint`가 항상 부모 thumb div를 돌려준다 — 기존 sr-only 면제(#289, `clipPath === inset(50%) && tabIndex < 0`)는 이 input이 진짜로 Tab이 닿는 자리(`tabIndex >= 0`)라 맞지 않았다. 그래서 "input 자체가 아니라 부모가 포인터를 받는" 새 분기 `native-range-thumb`를 `apps/storybook/test/stories.test.mjs`에 일반 패턴으로 추가했다 — 같은 recipe(숨은 네이티브 input + 클릭을 대신 받는 부모)를 쓰는 어떤 미래 컴포넌트에도 적용된다. 계기 자체 검증에 이 패턴의 self-test를 포함한다.

## 의존성과 base

출처: primitive·의존성 [#141](https://github.com/flameware/massive-design/issues/141) — [`../handoff/primitive-dependency-map.md`](../handoff/primitive-dependency-map.md)

- **The base is one, and the burden of proof is on whoever changes it** ([#152](https://github.com/flameware/massive-design/issues/152), [ADR-0016](../adr/0016-primitive-base-stays-radix.md)) — *the "one base" rule survives; the verdict below is 1세대. ADR-0023 §2 replaced it: the base is Base UI.* primitive stayed `radix-ui`; "upstream leads with it" is not by itself a reason. Counted from documentation, migration gains **one** confirmed thing (Base UI's `render` is a superset of `asChild`) against **three** losses (Accordion's roving focus removed, Tabs' `activateOnFocus` defaulting to manual against our shipped `automatic`, no standalone `Label`). The shape is a **conditional stay with four event-based triggers**, never a date. It binds **new** components too: a base that splits, splits by accident, not by judgement.
- **A dependency's weight is a floor cost, not a property of the library** ([#153](https://github.com/flameware/massive-design/issues/153), [ADR-0017](../adr/0017-dependency-weight-is-a-floor-cost.md)). The floor cost is what a consumer pays importing **zero** components. There is no single number to hang on a library — the same `recharts` is 8,371 B for `ResponsiveContainer` alone and 407,702 B through the chart body. What raises the floor is **packaging, not dependency choice** — an undeclared `sideEffects` — so the remedy is a declaration, never ripping the library out. `bun.lock` is the authority for reproducibility.

## 방법론

출처: 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221) · 2026-09 점검 [`../handoff/repo-review-2026-09.md`](../handoff/repo-review-2026-09.md)

- **Read the source, not the record about the source — and never read a population by eye, including your own bookkeeping** ([#166](https://github.com/flameware/massive-design/issues/166), [#174](https://github.com/flameware/massive-design/issues/174), [#195](https://github.com/flameware/massive-design/issues/195)). Eight times across twelve tickets a recorded claim did not match the source — a ticket's own premise, a cited ADR clause that said something else, three of five draft verdicts, a research doc's claim of a collision that never existed. A precedent transfers only where its premise holds (`Card`'s reason for closing `size` was written where the axis does not exist). A count that matters is one a script produced this generation, not one a document froze.
- **An issue is opened to change one of three things: the shape or API of a component or token a consumer uses, a defect met in a consuming app, or packaging and publishing** ([`repo-review-2026-09.md`](../handoff/repo-review-2026-09.md)). Gate, schema and vocabulary changes are opened only when one of those three is blocked by them. A title that says "re-measure", "close the gap" or "full cross-check" gets a second look — the same population was counted four times. Preventing an agent's mistake from recurring is one test line, not one rule paragraph.
- **A re-measurement reuses the generation's script, not a fresh one** ([Phase 2 #327](https://github.com/flameware/massive-design/issues/327), [`../handoff/phase-2-base-ui-map.md`](../handoff/phase-2-base-ui-map.md)). A different script gives a different number for the same population and the before/after comparison becomes meaningless — #317's line-count of "13 files, 32 lines" and #327's site-count of "8 files, 14 sites" were both honest, but only comparable to a later run of their own script. When a script exists for a population, later tickets that re-measure it run that script again.
- **An optional part's story coverage must walk every combination it allows, not just the ones a demo needs** ([Phase 2 #327](https://github.com/flameware/massive-design/issues/327) → [#349](https://github.com/flameware/massive-design/pull/349)). `EmptyState.Root` set `aria-describedby` unconditionally because all four DS stories rendered title and description together — the consuming app's conditional-description screen was the first render to walk the other path, and axe caught the defect there instead of in CI. *n* optional parts means *n* story combinations, not the one combination a demo happens to need.
- **A component's shipped DOM carries no test hooks — stories select by role and accessible name like every other story** ([Phase 2 ConfirmDialog #330](https://github.com/flameware/massive-design/issues/330), implementation note). A `data-testid` added to the source for convenience was reverted; the shared harness's `waitUntilFocused` was fixed instead so a Playwright-engine selector (`role=`, `text=`) routes through `Locator` rather than the plain-CSS `closest()` path that could not parse it.
- **A preset adoption reveals defects the hand-assembly hid, because the preset's contract is stricter** ([Phase 2 ConfirmDialog adoption #354](https://github.com/flameware/massive-design/issues/354)). Three delete handlers swallowed their `catch` — invisible while the confirm/cancel buttons were hand-assembled, because nothing read the outcome. `ConfirmDialog`'s loading state runs on `onConfirm`'s promise: a swallowed error resolves, so the dialog would have closed on a failed delete instead of staying open to retry. The adoption ticket fixed the three handlers rather than leaving the contract quietly wrong.
- **A minor bump raises `packages/ui`'s internal `@flameware/tokens` dependency range to the same version, in the same commit** ([Phase 3 #367](https://github.com/flameware/massive-design/issues/367), [`../handoff/phase-3-base-ui-map.md`](../handoff/phase-3-base-ui-map.md)). The first `v0.4.0` tag published `@flameware/tokens@0.4.0` but left `packages/ui/package.json`'s internal range at `^0.3.0` — the range `ui` requires excluded the `tokens` version that actually existed, so CI's `bun install --frozen-lockfile` failed to resolve the workspace and `publish.yml` died with a registry 404. Every prior minor bump (0.1.0→0.2.0→0.2.0→0.3.0) had raised both together by coincidence of scope; this one didn't. Before pushing a version tag, bump both `package.json`s and confirm `bun install --frozen-lockfile` reports "no changes" locally.
- **A compound object export is not destructured directly inside a Next.js Server Component** ([Phase 3 Toast landing #377](https://github.com/flameware/massive-design/issues/377), [`../handoff/phase-3-base-ui-map.md`](../handoff/phase-3-base-ui-map.md)). `Toast.Provider`/`Toast.Viewport` is a compound object like every other DS export, but used as `<Toast.Provider>` inside a root layout with no `"use client"`, the production build failed at `/_not-found` prerender ("Element type is invalid… got: undefined") — the RSC client-reference substitution wraps the whole object, so property access on it resolves to `undefined`. Hand-assembly never hit this boundary; landing did. The fix stays on the consumer's side (a thin client wrapper component, same shape as an existing `ThemeProvider` wrapper) — the DS API keeps shipping compound objects, because every *client*-component consumer of it is unaffected.
- **서버/클라이언트 분류의 정본은 `packages/ui/test/package.test.mjs`의 `CLIENT_SUBPATHS`/`SERVER_SUBPATHS`이고, `"use client"`를 붙이거나 붙이지 않는 이유는 주석에 남긴다** ([Icon #412](https://github.com/flameware/massive-design/issues/412), [`../handoff/second-consumer-onboarding-map.md`](../handoff/second-consumer-onboarding-map.md)). `Icon`은 훅·컨텍스트·이벤트 핸들러·브라우저 API를 하나도 안 쓰는 자체 스타일 primitive인데도 처음 커밋될 때부터 `"use client"`가 근거 없이 박혀 있었다 — Server Component에서 `icon` prop으로 함수 레퍼런스를 그대로 넘기면 RSC 경계를 못 건너 빌드가 깨졌다(README의 Alert 예시가 정확히 이 패턴). 문서로 우회하지 않고 지시어를 걷어내 `SERVER_SUBPATHS`로 옮겼다 — Card·Alert가 이미 같은 판정을 받은 자리와 같다. 다음 컴포넌트를 분류할 때도 `package.test.mjs`의 두 스모크 테스트("클라이언트 경계는 패키지가 박는다"/"자체 스타일 primitive는 서버로 남는다")가 이 계약을 진다.
- **앱 개발자가 읽는 한국어 글은 [`writing-ko.md`](writing-ko.md)를 따르고, 그 규칙은 승인된 실제 페이지에서 뽑는다** ([한국어 글쓰기 맵 #425](https://github.com/flameware/massive-design/issues/425), [`../handoff/korean-writing-map.md`](../handoff/korean-writing-map.md)). 대상은 Storybook MDX·패키지 README·온보딩 가이드·공개 API 에러 메시지이고, ADR·이슈·`../handoff/`·`CONTEXT.md` 정의문·커밋 메시지는 대상이 아니다. **페이지 뼈대**는 한 줄 요약 → (컴포넌트면 "언제 쓰는가 / 언제 쓰지 않는가") → 사용법 → 주의할 점 → 배경이고, 설계 논증은 3~4문장 이하의 배경 절이나 ADR 링크로 내린다 — 첫 문장이 도입 서사면 독자가 거기서 멈춘다. 문체·단어 표현표·금지 패턴·전후 비교·PR에서 돌릴 `grep` 명령은 `writing-ko.md`에 있다(여기 옮겨 적지 않는다). 규칙 문서를 먼저 쓰지 않은 것이 이 맵의 방법이다 — 메인테이너가 승인한 기준 페이지 하나에서 규칙을 뽑아야 추상적인 문장이 되지 않는다.
- **앱 개발자가 받는 에러 메시지는 원인 → 수치·입력값 → 해결 방법 순서의 해요체이고, 테스트는 문구가 아니라 함수 이름·토큰 조합·수치를 확인한다** ([#433](https://github.com/flameware/massive-design/issues/433), [`../handoff/korean-writing-map.md`](../handoff/korean-writing-map.md)). 문구를 정규식으로 박아 둔 테스트는 문장을 다듬을 때마다 깨지고, 핵심 정보가 빠지는 것은 못 잡는다. 메시지 문자열에는 백틱을 쓰지 않는다(터미널에 그대로 찍힌다) — 식별자는 원어 평문으로 남는다. 실패 조합이 여럿이면 줄마다 쓴다: 대비 검사 실패는 한 키에서 19개까지 나와 한 줄에 이으면 해결 안내가 목록에 묻힌다. 메인테이너가 보는 CLI 출력(`lintRamp`의 검사 문구)과 내부 문서의 실패 조건 표는 이 규칙 밖이다. 에러 문장만 바뀐 변경은 공개 API 형태를 바꾸지 않으므로 **patch**로 게시한다(`0.6.2`).
- **용어집의 "다른 말로 부르지 말 것"은 내부 문서와 코드에만 적용된다** ([#426](https://github.com/flameware/massive-design/issues/426), [`../handoff/korean-writing-map.md`](../handoff/korean-writing-map.md)). 앱 개발자가 읽는 글은 용어집 항목의 `_문서에서는_` 줄을 따른다 — 그 예외가 `CONTEXT.md` 머리말에 적혀 있다. 소비처·축 같은 내부 용어는 이슈·ADR·코드에서 그대로 쓴다. 둘이 어긋나면 용어집이 정본이고 `writing-ko.md`의 표를 고친다.
- **루트 README는 허브이고, 레포 카드는 그것과 같은 말을 한다** ([루트 README 맵 #445](https://github.com/flameware/massive-design/issues/445), [`../handoff/root-readme-map.md`](../handoff/root-readme-map.md)). 1순위 독자가 레포를 처음 연 방문자라는 것과 설치·API를 링크로 넘긴다는 것은 [`writing-ko.md`](writing-ko.md)가 이미 진다 — 여기 더하는 것은 **README 밖의 두 자리**다. 하나, 레포 설명·토픽·Homepage는 README 첫 화면과 뜻이 같아야 하므로 README를 고칠 때 함께 본다(#448). 둘, 손으로 유지되는 컴포넌트 표는 컴포넌트를 더할 때 갱신하며 그 단계는 작업 폴더 가까이(`../../apps/storybook/README.md`의 "컴포넌트를 하나 더할 때")에 있다 — 규칙을 작업 폴더 가까이 두는 [#425](https://github.com/flameware/massive-design/issues/425)의 장치와 같다. 낡는 스크린샷·GIF를 두지 않는 것도 이 README의 결정이다(Storybook 링크가 그 역할이다).
- **소비처 대면 설정 지식은 `docs/consumer-onboarding.md` 한 장에 모으고, 패키지 README는 그 문서를 가리키기만 한다** ([#403](https://github.com/flameware/massive-design/issues/403), [`../handoff/second-consumer-onboarding-map.md`](../handoff/second-consumer-onboarding-map.md)). `.npmrc`/토큰, CSS import 순서, 폰트, 다크 모드(`.dark` 클래스만 보고 OS 추종은 소비처의 `<head>` 인라인 스크립트 몫), brand 키 오버라이드, RSC 경계(#377·#412), Next 16/`bun link` 함정, ADR-0025 대조표가 모두 이 한 문서에 있다. **`bun link`가 만드는 심링크는 Next 16 Turbopack에서 `@flameware/ui`의 서브패스 export를 통째로 못 푼다**(webpack은 된다, DS 결함 아님) — 아직 게시 안 된 로컬 변경을 앱에 미리 붙여볼 때는 `bun link` 대신 `npm pack` tarball을 쓴다.
