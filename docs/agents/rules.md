# 규칙 원장

나중 작업을 구속하는 **디자인 시스템의** 규칙. 각 규칙은 원문 그대로이고, 그 규칙을 낳은 맵의 서술은 `../handoff/`의 완료 기록에 있다. 매니페스트 생성기와 게이트의 **내부 규약**은 여기 없다 — [`packages/ui/scripts/manifest/README.md`](../../packages/ui/scripts/manifest/README.md)에 있다(2026-09 점검에서 옮겼다).

주제별로 묶었다 — 맵 연대순이 아니다. 무언가를 하기 전에 그것을 구속하는 규칙이 있는지 이 순서로 찾으면 된다.

## 무엇이 컴포넌트가 되는가

출처: P1 [#88](https://github.com/flameware/massive-design/issues/88) · P2 [#118](https://github.com/flameware/massive-design/issues/118) — [`../handoff/catalog-maps.md`](../handoff/catalog-maps.md)

- **An item that derived channels cannot tell apart does not get its own component** ([#97](https://github.com/flameware/massive-design/issues/97)). Manifests and Figma carry anatomy and configuration state, not behaviour, so a behaviour-only variant cannot satisfy the "code, Storybook and Figma in one generation" completion definition. This is the rule that ruled Drawer out against Sheet, and it governs P2 triage.
- **A composed component consumes the original rather than copying it** ([#91](https://github.com/flameware/massive-design/issues/91)). Combobox imports Command and Popover; copying would fork their keyboard contracts.

## 계약이 무엇을 담는가

출처: P2 [#118](https://github.com/flameware/massive-design/issues/118) · 파생 채널 [#140](https://github.com/flameware/massive-design/issues/140) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221)

- **`anatomy` names what the consumer assembles** ([#172](https://github.com/flameware/massive-design/issues/172), [ADR-0018](../adr/0018-anatomy-is-the-consumer-assembly.md)). A node the component renders on its own is not anatomy however real it is in the tree. Portal was public on three components and not on four, and the asymmetry was not a gate failing to reach a surface — the three were simply **opened without grounds**, and their export never worked: `Content` wraps its own Portal, so a consumer's `container` was silently ignored. Its corollary is that `breaking` can be *executed* while the package is private, unpublished and unconsumed — and the trigger that closes that path is the **first npm publish**, an event, never a date.
- **A third-party library owns the nodes we do not give a `className` to, and the contract must say so** ([#122](https://github.com/flameware/massive-design/issues/122)). The boundary is class ownership; each externally-owned surface is listed in `externalSurfaces` with its own reason. Ownership reaches further than nodes — it takes inline styles ([#124](https://github.com/flameware/massive-design/issues/124)) and prop name spaces ([#125](https://github.com/flameware/massive-design/issues/125)) too. Its corollary: **we do not re-export a third-party component through our barrel**, because a surface cannot be ours and theirs at once.
- **What derived channels do not carry, the contract declares and a person verifies — and the boundary is the cause** ([#149](https://github.com/flameware/massive-design/issues/149), [#187](https://github.com/flameware/massive-design/issues/187), [0010](../../packages/ui/scripts/manifest/decisions/0010-behaviors-are-declared-and-human-verified.md), [0015](../../packages/ui/scripts/manifest/decisions/0015-behaviors-boundary-is-the-cause.md)). `behaviors` takes interactions whose cause is **not an explicit activation** (hover, drag, long press, a timer, focus arriving, typing at a *closed* control) in three kinds — `control-gesture`, `open-cause`, `implicit-change`. It does not take what the role already requires (arrow movement and highlighting inside an open surface, Escape and outside-press dismissal, click activation, and the defaults hanging off those), nor changes a person did not cause (image load, password-manager detection, container resize). All 51 contracts were surveyed against the sources `bun.lock` pins, so `behaviors: {}` means "confirmed it brings nothing". `bun run sync:checklist` prints the human checklist from the contracts; a list kept by hand leaked three times.
- **`reference.guidance` speaks to the consumer, never to the next maintainer** ([ADR-0022](../adr/0022-guidance-is-for-the-consumer.md)). `use` and `limits` answer "do I reach for this here" — `limits` must name the alternative, never end on "don't use this". `evidence` records which consumer need opened the component and is maintainer information. A sentence that answers "why did we build it this way" is **rationale, not guidance** — it lives next to the declaration it explains (a source comment) or as an ADR pointer, never as prose inside `limits`. `check` enforces the shape mechanically (length caps: `use` 120, `evidence` 150, `limits` 200; no issue numbers inside `limits`).

## 축과 이름 공간

출처: 표면 층위 공백 [#139](https://github.com/flameware/massive-design/issues/139) · 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221)

- **A new axis's default is the value that preserves published instances** ([#139](https://github.com/flameware/massive-design/issues/139)'s four batches). `knockout: none`, `placement: auto`, `frame: none` (but `icon` for `EmptyMedia`, because that is what it already rendered), `spacing: separate`, `indicator: pill`, `rank: legend` — in every case the default is the value the part already rendered, which is what makes opening an axis `additive` rather than a reinterpretation of instances already published. "The default emits no class" is the wrong gloss: only three of the six emit `""`, while `frame`, `indicator` and `rank` name a shape the part was already drawing.
- **An axis name must not already mean something else in the catalog** ([#125](https://github.com/flameware/massive-design/issues/125), [ADR-0008](../adr/0008-axis-and-value-name-spaces.md)). Upstream's name is the default choice, but only if it is free here — `align` was taken twice over, so the addon axis became `placement`; `variant` already names the root's semantic/emphasis axis, so the media slot became `frame`, the tab marker `indicator`, the field caption's tier `rank`. **A part-level axis name answers the same test one level down** ([#224](https://github.com/flameware/massive-design/issues/224)): a part introduces `variant` only when its root has none ([ADR-0019](../adr/0019-what-variant-names.md) decision 1 as amended) — `DropdownMenuItem.variant` is the first case; where the root does have `variant`, a part inherits it (`ToggleGroupItem.variant`, [#179](https://github.com/flameware/massive-design/issues/179)). **Value names are the other way round: their name space is the axis, not the catalog** — `chart.indicator`'s `line` and `tabs.indicator`'s `line` mean different pictures. And a value names the state of *what the axis names*, never whether a class is emitted: `frame: none` means no frame, not no class. No gate sees this — it is a meaning judgement.
- **`variant` names how the root itself stands, and a component fills only the dimensions that apply** ([#173](https://github.com/flameware/massive-design/issues/173), [ADR-0019](../adr/0019-what-variant-names.md)). Across the catalog the axis carries three — meaning, emphasis, form — and `Badge` filling only meaning is no more a deviation than `Item` filling only emphasis. Mixing two in one axis is not forbidden either: `Button` already ships `default·destructive·outline·secondary·ghost·link`. The rule that survives is that **adding a dimension needs measured demand**, and whether it arrives on the same axis or a second one is decided by whether the derived channels must multiply the two.

## 토큰과 대비

출처: P2 [#118](https://github.com/flameware/massive-design/issues/118)

- **A contrast requirement follows the role, not the token family** ([#109](https://github.com/flameware/massive-design/issues/109)). WCAG 1.4.11 binds "UI components that indicate state", so a *fill* can be inside the non-text gate: a **control affordance** — Scroll Area's thumb, Switch's off track — is the thing you grab, so it owes 3:1 against the surface it sits on and takes `bg.neutral.solid` (alias `neutral-solid`, [ADR-0003](../adr/0003-neutral-solid-alias-name.md)). Its opposite, the **track remainder** (Progress, Slider), owes nothing, because the filled part carries the meaning. Both roles are defined in `CONTEXT.md`. Four places had agreed on neutral 3 by accident, reached through three different paths; two of them were invisible at 1.09:1 and 1.17:1 and passed three gates in silence. `CODE_VERIFIED` is not a disproof of a defect no gate is looking for.

## 포인터 기하

출처: 터치 대상 크기 [#111](https://github.com/flameware/massive-design/issues/111) — [`../handoff/pointer-target-map.md`](../handoff/pointer-target-map.md) · [ADR-0020](../adr/0020-pointer-target-size-is-borne-by-the-hit-area.md)

- **The floor is WCAG 2.5.8 (AA) 24×24 CSS px, borne by the hit area; the visual dimension does not move** (ADR-0020 decisions 1·2). AAA 44 is consumer advice in `CONTEXT.md`, never contract — its spacing exception is a condition the consumer's layout creates. The rule binds every pointer unconditionally: no `pointer: coarse` branch, because derived channels cannot tell the two apart (decision 3).
- **The mechanism is a transparent `after:` (or `before:` where `after:` already draws) pseudo-element, expanded centre-symmetrically to 24, and it stands aside for externally owned surfaces** (decision 4, [#230](https://github.com/flameware/massive-design/issues/230), [#249](https://github.com/flameware/massive-design/issues/249)). Overlap with a neighbour is **declared, not solved** — the gate computes the excess, no contract field carries it, and the consumer judges (decision 5). Two traps the instrument caught: an absolute pseudo-element's containing block is the padding box, and widening one axis without `inset-*-0` on the other collapses it to zero.
- **`after`·`before` stay `ignore:` in the policy table, and the floor is measured by a separate tool** (decision 6, [#232](https://github.com/flameware/massive-design/issues/232)). `bun run pointer-gate` diffs rendered hit areas against the committed baseline; a place the rule cannot reach is a named row in `docs/research/pointer-target-exceptions.json` with its reason, never a widened `ignore:`. The gate is not on CI — promotion waits on a regression reproducing across generations.

## 의존성과 base

출처: primitive·의존성 [#141](https://github.com/flameware/massive-design/issues/141) — [`../handoff/primitive-dependency-map.md`](../handoff/primitive-dependency-map.md)

- **The base is one, and the burden of proof is on whoever changes it** ([#152](https://github.com/flameware/massive-design/issues/152), [ADR-0016](../adr/0016-primitive-base-stays-radix.md)). primitive stays `radix-ui`; "upstream leads with it" is not by itself a reason. Counted from documentation, migration gains **one** confirmed thing (Base UI's `render` is a superset of `asChild`) against **three** losses (Accordion's roving focus removed, Tabs' `activateOnFocus` defaulting to manual against our shipped `automatic`, no standalone `Label`). The shape is a **conditional stay with four event-based triggers**, never a date. It binds **new** components too: a base that splits, splits by accident, not by judgement.
- **A dependency's weight is a floor cost, not a property of the library** ([#153](https://github.com/flameware/massive-design/issues/153), [ADR-0017](../adr/0017-dependency-weight-is-a-floor-cost.md)). The floor cost is what a consumer pays importing **zero** components. There is no single number to hang on a library — the same `recharts` is 8,371 B for `ResponsiveContainer` alone and 407,702 B through the chart body. What raises the floor is **packaging, not dependency choice** — an undeclared `sideEffects` — so the remedy is a declaration, never ripping the library out. `bun.lock` is the authority for reproducibility.

## 방법론

출처: 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221) · 2026-09 점검 [`../handoff/repo-review-2026-09.md`](../handoff/repo-review-2026-09.md)

- **Read the source, not the record about the source — and never read a population by eye, including your own bookkeeping** ([#166](https://github.com/flameware/massive-design/issues/166), [#174](https://github.com/flameware/massive-design/issues/174), [#195](https://github.com/flameware/massive-design/issues/195)). Eight times across twelve tickets a recorded claim did not match the source — a ticket's own premise, a cited ADR clause that said something else, three of five draft verdicts, a research doc's claim of a collision that never existed. A precedent transfers only where its premise holds (`Card`'s reason for closing `size` was written where the axis does not exist). A count that matters is one a script produced this generation, not one a document froze.
- **An issue is opened to change one of three things: the shape or API of a component or token a consumer uses, a defect met in a consuming app, or packaging and publishing** ([`repo-review-2026-09.md`](../handoff/repo-review-2026-09.md)). Gate, schema and vocabulary changes are opened only when one of those three is blocked by them. A title that says "re-measure", "close the gap" or "full cross-check" gets a second look — the same population was counted four times. Preventing an agent's mistake from recurring is one test line, not one rule paragraph.
