# 규칙 원장

카탈로그 맵들이 남긴, 나중 작업을 구속하는 규칙 전부. 각 규칙은 원문 그대로이고, 그 규칙을 낳은 맵의 서술은 `../handoff/`의 완료 기록에 있다.

주제별로 묶었다 — 맵 연대순이 아니다. 무언가를 하기 전에 그것을 구속하는 규칙이 있는지 이 순서로 찾으면 된다.

## 무엇이 컴포넌트가 되는가

출처: P1 [#88](https://github.com/flameware/massive-design/issues/88) · P2 [#118](https://github.com/flameware/massive-design/issues/118) — [`../handoff/catalog-maps.md`](../handoff/catalog-maps.md)

- **An item that derived channels cannot tell apart does not get its own component** ([#97](https://github.com/flameware/massive-design/issues/97)). Manifests and Figma carry anatomy and configuration state, not behaviour, so a behaviour-only variant cannot satisfy the "code, Storybook and Figma in one generation" completion definition. This is the rule that ruled Drawer out against Sheet, and it governs P2 triage.
- **A composed component consumes the original rather than copying it** ([#91](https://github.com/flameware/massive-design/issues/91)). Combobox imports Command and Popover; copying would fork their keyboard contracts.

## 계약이 무엇을 담고, 게이트가 무엇을 보는가

출처: P2 [#118](https://github.com/flameware/massive-design/issues/118) · 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) · 파생 채널 [#140](https://github.com/flameware/massive-design/issues/140) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221)

- **`anatomy` names what the consumer assembles** ([#172](https://github.com/flameware/massive-design/issues/172), [ADR-0018](../adr/0018-anatomy-is-the-consumer-assembly.md)). A node the component renders on its own is not anatomy however real it is in the tree. Portal was public on three components and not on four, and the asymmetry was not a gate failing to reach a surface — ⓐ·ⓑ were fine, the three were simply **opened without grounds**, and their export never worked: `Content` wraps its own Portal, so a consumer's `container` was silently ignored. What was missing was not a gate but a **definition**. Its corollary is that `breaking` can be *executed* while the package is private, unpublished and unconsumed — and the trigger that closes that path is the **first npm publish**, an event, never a date.
- **A third-party library owns the nodes we do not give a `className` to, and the contract must say so** ([#122](https://github.com/flameware/massive-design/issues/122)). The boundary is class ownership; each externally-owned surface is listed in `externalSurfaces` with its own reason. Ownership reaches further than nodes — it takes inline styles ([#124](https://github.com/flameware/massive-design/issues/124)) and prop name spaces ([#125](https://github.com/flameware/massive-design/issues/125)) too. Its corollary: **we do not re-export a third-party component through our barrel**, because a surface cannot be ours and theirs at once.
- **A grade of "not in this cell" is not one thing but four** ([#180](https://github.com/flameware/massive-design/issues/180), [ADR-0012](../adr/0012-drawn-elsewhere.md)). `unresolved` (not handled yet) · `ignore:` (never there) · `externalSurfaces` (not ours) · `elsewhere:` (there, not here). ② and ④ are split by **whether it is drawn**, ③ and ④ by **owner versus place**, and `elsewhere:` must name *where* that place is. Its corollary is the map's own method: when a signal mixes grades you cannot read what it points at, so the fix is always to add the grade, never to widen `ignore:`.
- **"Not in this cell" is silence, and the gate measures it against source, never against a `parts` key** ([#195](https://github.com/flameware/massive-design/issues/195), [#246](https://github.com/flameware/massive-design/issues/246)). The definition is the union: a node's class token is reached only if it sits in the manifest's root cell ∪ `parts` cell, so having a `parts` key at all proves nothing by itself. A recorded exclusion from that count only enters as a claim the gate can disprove — `elsewhere:` (the missing tokens live in another contract's cell) or `overriddenBy:` (a listed class wins over them through `tailwind-merge`) in `parts-coverage.exceptions.json` — never as a bare name a gate takes on faith; a node that starts reaching makes its own exception stale, and a stale exception is red, the same shape as `elsewhere:`'s use in ADR-0012.
- **An unprefixed anatomy name gets an unprefixed `parts` key** ([#243](https://github.com/flameware/massive-design/issues/243)). The gate compares the anatomy string verbatim, so `Indicator`·`Thumb` register without a component prefix.
- **The policy table holds meanings; shape is peeled off before lookup, and a chain is a path** ([#178](https://github.com/flameware/massive-design/issues/178), [#182](https://github.com/flameware/massive-design/issues/182), [ADR-0014](../adr/0014-modifier-chains-are-paths.md)). A term binds the **subject** at that position and only a slot designator moves the subject, so order changes meaning only through subject movement (`[&_svg]:disabled` ≡ `svg:disabled`). Never widen the table to compound keys — it grows with the combinations and leaks at the next chain.
- **The contract bears the label, and the gate only ever checks the declaration for falsehood** ([#148](https://github.com/flameware/massive-design/issues/148), [#181](https://github.com/flameware/massive-design/issues/181), [#184](https://github.com/flameware/massive-design/issues/184), [ADR-0009](../adr/0009-drawn-but-not-carried.md), [ADR-0013](../adr/0013-slot-labels-are-borne-by-the-contract.md)). `drawnBy` says what draws each configuration state and `slots` names a designated descendant — except where **the selector states the role itself** (`[&_svg]` means "an icon anywhere"), which is the one line on the other side. Where a hand-written sentence could diverge from the policy table, the gate asks the table back rather than trusting a copy.
- **What derived channels do not carry, the contract declares and a person verifies — and the boundary is the cause** ([#149](https://github.com/flameware/massive-design/issues/149), [#187](https://github.com/flameware/massive-design/issues/187), [ADR-0010](../adr/0010-behaviors-are-declared-and-human-verified.md), [ADR-0015](../adr/0015-behaviors-boundary-is-the-cause.md)). `behaviors` takes interactions whose cause is **not an explicit activation** (hover, drag, long press, a timer, focus arriving, typing at a *closed* control) in three kinds — `control-gesture`, `open-cause`, `implicit-change`. It does not take what the role already requires (arrow movement and highlighting inside an open surface, Escape and outside-press dismissal, click activation, and the defaults hanging off those: `loop`, `modal`, focus trap, scroll lock), nor changes a person did not cause (image load, password-manager detection, container resize). All 51 contracts were surveyed against the sources `bun.lock` pins — **not the docs, which do not tell you the version we installed** — so `behaviors: {}` now means "confirmed it brings nothing". `bun run sync:checklist` prints the human checklist from the contracts; a list kept by hand leaked three times.
- **`reference.guidance` speaks to the consumer, never to the next maintainer** ([ADR-0022](../adr/0022-guidance-is-for-the-consumer.md)). `use` and `limits` answer "do I reach for this here" — `limits` must name the alternative, never end on "don't use this". `evidence` records which consumer need opened the component and is maintainer information, not the screen's lead. A sentence that answers "why did we build it this way" is **rationale, not guidance** — it lives next to the declaration it explains (a source comment) or, once a real trade-off is behind it, as an ADR pointer line in the contract — never as prose inside `limits`. `check` enforces the shape mechanically: a length cap per field (`use` 120, `evidence` 150, `limits` 200) and a ban on issue numbers or ADR prose inside `limits` — it cannot judge tone, so it only catches the field growing back into a rationale dump. The population that needs decomposing is never read by eye ([#165](https://github.com/flameware/massive-design/issues/165)'s rule, applied here): `bun run check` prints it.

## 축과 이름 공간

출처: 표면 층위 공백 [#139](https://github.com/flameware/massive-design/issues/139) · 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221)

- **A new axis's default is the value that preserves published instances** ([#139](https://github.com/flameware/massive-design/issues/139)'s four batches). `knockout: none`, `placement: auto`, `frame: none` (but `icon` for `EmptyMedia`, because that is what it already rendered), `spacing: separate`, `indicator: pill`, `rank: legend` — in every case the default is the value the part already rendered, which is what makes opening an axis `additive` rather than a reinterpretation of instances already published to Figma. "The default emits no class" is the wrong gloss and it misled: only three of the six emit `""`, while `frame`, `indicator` and `rank` name a shape the part was already drawing. `rank: legend` is the sharpest case ([#164](https://github.com/flameware/massive-design/issues/164)): upstream's `legend` is a *different* shape from ours, because upstream's value names a **role** and its declaration differs across all eight style branches — so we took the role and drew it at the scale our published instances already had. [#161](https://github.com/flameware/massive-design/issues/161) re-measured this and kept all five names — see the next rule.
- **An axis name must not already mean something else in the catalog** ([#125](https://github.com/flameware/massive-design/issues/125)). Upstream's name is the default choice, but only if it is free here. `align` was taken twice over — by recharts' `Legend` props and by Radix's floating-surface alignment — so the addon axis became `placement` ([#144](https://github.com/flameware/massive-design/issues/144)); `variant` already names the root's semantic/emphasis axis, so the media slot became `frame` ([#145](https://github.com/flameware/massive-design/issues/145)), the tab marker became `indicator` ([#146](https://github.com/flameware/massive-design/issues/146)), and the field caption's tier became `rank` ([#164](https://github.com/flameware/massive-design/issues/164)). **A part-level axis name answers the same test, ADR-0008 rule 1, applied one level down: if the catalog already has a name for that meaning, that is the name** ([#224](https://github.com/flameware/massive-design/issues/224)) — which is why the sharpest instance of the general rule is its own line: a part introduces `variant` only when its root has none ([ADR-0019](../adr/0019-what-variant-names.md) decision 1, amended by [#224](https://github.com/flameware/massive-design/issues/224)/[#237](https://github.com/flameware/massive-design/issues/237)) — `DropdownMenuItem.variant`'s `default`·`destructive` is the first case, opened because the root carries no axis to collide with. Where the root does have `variant`, a part inherits it instead: `ToggleGroupItem.variant` is the root's own axis **inherited** onto the part ([#179](https://github.com/flameware/massive-design/issues/179)), which is the global name space working, not an exception to it. **Value names are the other way round: their name space is the axis, not the catalog** — `chart.indicator`'s `line` and `tabs.indicator`'s `line` mean different pictures and that is not a collision. And a value names the state of *what the axis names*, never whether a class is emitted: `frame: none` means no frame, not no class. So there is no shared name for a neutral default, and the five keep the five names they have ([ADR-0008](../adr/0008-axis-and-value-name-spaces.md), from [#161](https://github.com/flameware/massive-design/issues/161)). No gate sees this — it is a meaning judgement, and ADR-0006's rule against claiming what a gate cannot see applies.
- **`variant` names how the root itself stands, and a component fills only the dimensions that apply** ([#173](https://github.com/flameware/massive-design/issues/173), [ADR-0019](../adr/0019-what-variant-names.md)). Across the catalog the axis carries three — meaning, emphasis, form — and `Badge` filling only meaning is no more a deviation than `Item` filling only emphasis. Mixing two in one axis is not forbidden either: `Button` already ships `default·destructive·outline·secondary·ghost·link`. The rule that survives is that **adding a dimension needs measured demand**, and whether it arrives on the same axis or a second one is decided by whether the derived channels must multiply the two.

## 토큰과 대비

출처: P2 [#118](https://github.com/flameware/massive-design/issues/118)

- **A contrast requirement follows the role, not the token family** ([#109](https://github.com/flameware/massive-design/issues/109)). WCAG 1.4.11 binds "UI components that indicate state", so a *fill* can be inside the non-text gate: a **control affordance** — Scroll Area's thumb, Switch's off track — is the thing you grab, so it owes 3:1 against the surface it sits on and takes `bg.neutral.solid` (alias `neutral-solid`, [ADR-0003](../adr/0003-neutral-solid-alias-name.md)). Its opposite, the **track remainder** (Progress, Slider), owes nothing, because the filled part carries the meaning. Both roles are defined in `CONTEXT.md`. Four places had agreed on neutral 3 by accident, reached through three different paths (`bg-secondary`, `bg-muted`, and `--ds-state-base: var(--secondary)`); two of them were invisible at 1.09:1 and 1.17:1 and passed three gates in silence — `tokens:contrast` had no such pair, manifest lint rule 3 reads families and says so itself, and axe does not measure a custom scrollbar's affordance. `CODE_VERIFIED` is not a disproof of a defect no gate is looking for.

## 포인터 기하

출처: 터치 대상 크기 [#111](https://github.com/flameware/massive-design/issues/111) — [`../handoff/pointer-target-map.md`](../handoff/pointer-target-map.md) · [ADR-0020](../adr/0020-pointer-target-size-is-borne-by-the-hit-area.md)

- **The floor is WCAG 2.5.8 (AA) 24×24 CSS px, borne by the hit area; the visual dimension does not move** ([#111](https://github.com/flameware/massive-design/issues/111), ADR-0020 decisions 1·2). AAA 44 is consumer advice in `CONTEXT.md`, never contract — its spacing exception is a condition the consumer's layout creates. The rule binds every pointer unconditionally: no `pointer: coarse` branch, because derived channels cannot tell the two apart (decision 3).
- **The mechanism is a transparent `after:` (or `before:` where `after:` already draws) pseudo-element, expanded centre-symmetrically to 24, and it stands aside for externally owned surfaces** (decision 4, [#230](https://github.com/flameware/massive-design/issues/230), [#249](https://github.com/flameware/massive-design/issues/249)). Overlap with a neighbour is **declared, not solved** — the gate computes the excess, no contract field carries it, and the consumer judges (decision 5). Two traps the instrument caught: an absolute pseudo-element's containing block is the padding box, and widening one axis without `inset-*-0` on the other collapses it to zero.
- **`after`·`before` stay `ignore:` in the policy table, and the floor is measured by a separate tool** (decision 6, [#232](https://github.com/flameware/massive-design/issues/232)). `bun run pointer-gate` diffs rendered hit areas against the committed baseline; a place the rule cannot reach is a named row in `docs/research/pointer-target-exceptions.json` with its reason, never a widened `ignore:`. The gate is not on CI — promotion waits on a regression reproducing across generations.

## 의존성과 base

출처: primitive·의존성 [#141](https://github.com/flameware/massive-design/issues/141) — [`../handoff/primitive-dependency-map.md`](../handoff/primitive-dependency-map.md)

- **The base is one, and the burden of proof is on whoever changes it** ([#152](https://github.com/flameware/massive-design/issues/152), [ADR-0016](../adr/0016-primitive-base-stays-radix.md)). primitive stays `radix-ui`; "upstream leads with it" is not by itself a reason, which is [#118](https://github.com/flameware/massive-design/issues/118)'s rule 2 applied to the base itself. Counted from documentation, migration gains **one** confirmed thing (Base UI's `render` is a superset of `asChild`) against **three** losses (Accordion's roving focus removed, Tabs' `activateOnFocus` defaulting to manual against our shipped `automatic`, no standalone `Label`) — 23 of 24 components move grade for that. The shape is a **conditional stay with four event-based triggers**, never a date, because a date measures nothing. It binds **new** components too: a base that splits, splits by accident, not by judgement. The evidence grade is documentation-only, so re-adjudication carries [#150](https://github.com/flameware/massive-design/issues/150) §10's 23 unconfirmed items as a precondition — installed against the real thing.
- **A dependency's weight is a floor cost, not a property of the library** ([#153](https://github.com/flameware/massive-design/issues/153), [ADR-0017](../adr/0017-dependency-weight-is-a-floor-cost.md)). The floor cost is what a consumer pays importing **zero** components. There is no single number to hang on a library — the same `recharts` is 8,371 B for `ResponsiveContainer` alone and 407,702 B through the chart body — so a library-screening gate claims what a gate cannot see (ADR-0006). Install counts pointed the opposite way: the two packages with **zero** exclusive dependencies are the polluters, and the one with 37 adds nothing. What raises the floor is **packaging, not dependency choice** — an undeclared `sideEffects` — so the remedy is a declaration, never ripping the library out, and pricing accessibility behaviour by line count is exactly what [ADR-0016](../adr/0016-primitive-base-stays-radix.md) just refused. `bun.lock` is the authority for reproducibility; `package.json`'s pin-or-range is re-read as an intent to follow that library's minors, which is why only the base is a range.

## 방법론 — 모집단과 선례

출처: 종류 ② [#165](https://github.com/flameware/massive-design/issues/165) — [`../handoff/kind-2-surface-map.md`](../handoff/kind-2-surface-map.md) · parts 공백 닫기 [#221](https://github.com/flameware/massive-design/issues/221) — [`../handoff/parts-gap-map.md`](../handoff/parts-gap-map.md)

- **A precedent only transfers where its premise holds** ([#174](https://github.com/flameware/massive-design/issues/174)). `Card`'s reason for closing `size` — *the consumer settles spacing with a utility* — was written where the axis **does not exist**; it had never once been applied where it does. With an axis present the consumer must **overwrite** what the contract already emits, and the overwritten value never reaches a manifest, so a size that exists in code exists nowhere in the derived channels. Both `Item`'s `size: xs` and `Badge`'s fill kinds are therefore **conditional closes on measured demand**, not closes on precedent.
- **The population is never read by eye — including the population of your own bookkeeping.** This map wrote that rule down as its first, then computed its own claim against [#155](https://github.com/flameware/massive-design/issues/155) by reading a table: it said it would absorb three contracts when it absorbed **zero** ([#166](https://github.com/flameware/massive-design/issues/166) caught it by checking the table instead of obeying the instruction). Rule 1 had not been applied to itself. Eight times across twelve tickets a recorded claim turned out not to match the source — a ticket's own premise ([#172](https://github.com/flameware/massive-design/issues/172)), a cited ADR clause that said something else ([#173](https://github.com/flameware/massive-design/issues/173)), three of five draft verdicts ([#175](https://github.com/flameware/massive-design/issues/175)), a research doc's claim of a collision that never existed ([#174](https://github.com/flameware/massive-design/issues/174)). **The habit that caught all of them is the same one: read the source, not the record about the source.**
- **A population is what the gate produces each generation, not what a document freezes** ([#195](https://github.com/flameware/massive-design/issues/195), [#246](https://github.com/flameware/massive-design/issues/246)). [`docs/research/parts-population-2026-09.md`](https://github.com/flameware/massive-design/blob/main/docs/research/parts-population-2026-09.md) fixed the baseline that let this map charter its tickets, but the number that matters after charting is whatever `bun run check` prints — the research document is a snapshot, the gate is the re-derivation, and only the gate's number is load-bearing once work starts.
