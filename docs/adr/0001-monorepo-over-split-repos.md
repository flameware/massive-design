# ADR-0001 · React/Storybook을 별도 리포로 두지 않고 모노리포로 합친다

- **상태**: 채택
- **날짜**: 2026-08-20
- **근거 티켓**: [#12](https://github.com/flameware/massive-design/issues/12) · 맵 [#1](https://github.com/flameware/massive-design/issues/1)

## 맥락

토큰 맵을 차팅할 때 "이 리포는 토큰 원본 + 빌드 + Figma 주입까지. React/Storybook은 별도 리포"로 정했다. 이 결정은 프로젝트 시작 시점에 **요구사항이 드러나기 전** 내려졌고, 근거는 "관리할 영역을 나누는 편이 명확하다"는 일반론이었다. 에이전트(Claude)의 권고였고 사용자에게 별도 리포에 대한 요구는 없었다.

#12에서 인계 가이드를 쓰려고 그 결정의 **실무**를 구체화하자 청구서가 처음으로 드러났다.

## 결정

**모노리포로 합친다.** `packages/tokens` · `packages/ui` · `apps/storybook`을 워크스페이스로 두고, Figma 주입도 이 리포에 남긴다.

소비처인 invest diary는 이 논의 밖이다 — 별개 앱이고 계속 `dist/tokens.css`를 복사해 간다.

## 근거

분리를 유지하는 비용이 구체화됐고, 그에 대응하는 편익이 없었다.

**비용 (분리를 유지할 경우)**
- 컴포넌트 구조가 리포 경계를 건너야 하므로 매니페스트 빌드가 **필수**가 된다 (합치면 선택)
- 리포를 건너는 수동 복사가 둘 (`dist/tokens.css`, 매니페스트)
- **맵이 두 디렉터리를 오간다.** 맵과 티켓은 GitHub 이슈라 리모트에 묶이는데, 다른 리포에서 세션을 열면 이 리포의 에이전트 규약(`CLAUDE.md`, 이슈 트래커 규약)이 안 보인다. 새 리포에 되가리키는 규약 파일을 심어 우회해야 한다
- 매니페스트가 낡아도 **CI가 잡을 수 없다** — 소스가 다른 리포에 있다

**편익 (분리가 사는 이유)**
- 독립 버저닝·독립 배포. 그런데 **npm 배포는 out of scope**이고 소비처는 하나다
- 관심사 분리. 그런데 워크스페이스가 그걸 파일 구조로 똑같이 표현한다

즉 분리의 편익은 전부 워크스페이스로 얻어지고, 비용만 남는다.

**추가로 모노리포를 지지한 것**: 이 프로젝트는 포트폴리오이자 작업 방식 논의용 예시라 **관객이 있다.** 공유할 링크가 하나인 편이 낫고, "토큰 패키지와 UI 패키지의 경계가 파일 구조에 보인다"는 것 자체가 읽는 사람에게 전달되는 정보다.

## 대가

- 리포 하나가 커진다. 토큰만 보러 온 사람이 Storybook 앱까지 클론한다
- 워크스페이스라는 개념이 하나 추가된다 (사용자가 처음 쓴다)
- npm 배포로 승격할 때 패키지 경계를 새로 그을 필요는 없지만, 각 패키지의 `package.json`을 배포 가능한 형태로 다듬는 일은 남는다

되돌리기 비용은 **비대칭적으로 낮다** — 나중에 쪼개는 건 디렉터리를 들어내 새 리포에 넣는 일이지만, 지금 분리해 뒀다가 합치는 건 히스토리 병합이다. 확신이 없을 때는 합쳐 두는 쪽이 옵션을 더 많이 남긴다.

## 함께 정한 것

**패키지 매니저는 bun, 런타임은 node.** `bun install`이 설치·워크스페이스를 관리하고 토큰 빌드는 `node scripts/build.mjs` 그대로다 — 기존의 `node --test` 결정이 안 바뀐다. bun 워크스페이스 + Vite 조합의 Storybook에 경로 해석 이슈가 보고돼 있어([storybook#28335](https://github.com/storybookjs/storybook/discussions/28335)) **Storybook 세팅이 시험대**다. 터지면 npm으로 후퇴한다 — `workspaces` 선언이 매니저마다 동일해 잠금 파일 교체 하나다.
