# 패키지 스코프는 레지스트리 소유자를 따른다 — `@massive/*`를 `@flameware/*`로 바꾼다

상태: accepted · 2026-09-10 · [ADR-0023](0023-second-generation-base-ui.md) §4의 패키지 이름을 대체한다

ADR-0023 §4는 배포 대상을 GitHub Packages로 정하고 패키지를 `@massive/tokens`·`@massive/ui`로 적었다. 두 결정이 같은 문장에 있었지만 서로 맞지 않는다.

## 결정

두 패키지를 **`@flameware/tokens`·`@flameware/ui`**로 개명한다.

GitHub Packages의 npm 레지스트리는 패키지 스코프가 리포를 소유한 계정·조직 이름과 같을 것을 요구한다. 이 리포의 소유자는 `flameware`이므로 `@massive/*`는 게시 시점에 400으로 막힌다. 이름을 지금 바꾸는 것은 소비처가 아직 하나도 설치하지 않았기 때문이다 — invest diary가 `@massive/ui`를 물고 난 뒤에 알았다면 개명이 소비처의 이행 작업이 된다.

고려한 대안 둘:

- **`massive` GitHub 조직을 만들고 리포를 옮긴다.** 이름은 지키지만 리포 이전은 이 티켓(#278)이 감당할 일이 아니고, 조직 하나를 이름 때문에 만드는 것은 뒤집기 어려운 결정이다. 조직이 생기면 그때 다시 개명하면 된다 — 그쪽 방향의 개명도 소비처가 하나일 때가 가장 싸다.
- **공개 npm에 `@massive/*`로 올린다.** ADR-0023 §4가 GitHub Packages를 고른 이유(비공개 유지)를 버린다.

## 파급

- 리포 이름 `massive-design`, 디자인 시스템의 이름, `--ds-*` 변수 접두사는 **바뀌지 않는다.** 바뀐 것은 npm 스코프 하나다.
- 1세대를 서술하는 문서(`docs/adr/0001`–`0022`, `docs/handoff/`, `docs/research/`)의 `@massive/*`는 **그대로 둔다.** 그것은 그때 그 이름으로 있던 것에 대한 기록이다. 기록을 지금 이름으로 고쳐 쓰면 "기록이 원본과 다르다"는, 이 리포가 여덟 번 겪은 실패를 스스로 만든다(`rules.md` 방법론).
- `CONTEXT.md`의 1세대 용어 항목(매니페스트·번역표)도 같은 이유로 `@massive/*`를 유지한다.
