# 표면 층위 공백 닫기 맵 완료 기록

## What the map reached

The **표면 층위 공백 닫기** map ([#139](https://github.com/flameware/massive-design/issues/139)) has now opened all eight promoted surfaces: Avatar's badge/group/count ([#143](https://github.com/flameware/massive-design/issues/143), which stood up `--ds-border-knockout` and [ADR-0007](../adr/0007-knockout-border.md)), `AlertAction` and the addon `placement` axis ([#144](https://github.com/flameware/massive-design/issues/144)), the `frame` axis shared by `ItemMedia` and `EmptyMedia` ([#145](https://github.com/flameware/massive-design/issues/145)), Toggle Group `spacing` and Tabs `indicator` ([#146](https://github.com/flameware/massive-design/issues/146)), Dropdown Menu's six check/radio/submenu parts ([#142](https://github.com/flameware/massive-design/issues/142) adjudicated them, [#154](https://github.com/flameware/massive-design/issues/154) built them), and `FieldLegend`'s `rank` axis ([#164](https://github.com/flameware/massive-design/issues/164)). Zero new tokens across all six generations. The cross-batch axis vocabulary closed with no rename ([#161](https://github.com/flameware/massive-design/issues/161), [ADR-0008](../adr/0008-axis-and-value-name-spaces.md)). **The eighth was found by a recheck, not by the map** ([#162](https://github.com/flameware/massive-design/issues/162)): Field was named in the destination's roster but never got an implementation ticket, so for five generations the map said it had opened eight when it had opened seven. That recheck also disproved the map's corollary — opening the whole roster does *not* leave the surface-level gap at zero — and named why: [#121](https://github.com/flameware/massive-design/issues/121)'s census took its population from a **table's diff column** rather than from an identifier set, so the unit of comparison was a row, not a name, and everything on a "no change" row fell out. Dropdown Menu ([#127](https://github.com/flameware/massive-design/issues/127)) was not an exception to that but its one noticed instance. The fix is a mechanical set difference between upstream's registry source and our `publicExports`/manifest `axes`, and per ADR-0006 it is **not** a gate — the procedure and its reproduction commands are the runbook [`docs/agents/upstream-surface-recount.md`](../agents/upstream-surface-recount.md) ([#176](https://github.com/flameware/massive-design/issues/176)), which every later upstream recheck starts from. The 15 surfaces it turned up across 9 components are a new population and go out as their own map. That map is [#165](https://github.com/flameware/massive-design/issues/165) below, and it is complete.
