## Where the work stands

The **토큰 파운데이션** map ([#1](https://github.com/flameware/massive-design/issues/1)), **컴포넌트 맵** ([#14](https://github.com/flameware/massive-design/issues/14)), **P0 카탈로그 확장 구현 맵** ([#78](https://github.com/flameware/massive-design/issues/78)), **P1 카탈로그 확장 구현 맵** ([#88](https://github.com/flameware/massive-design/issues/88)), and **P2 카탈로그 확장 구현 맵** ([#118](https://github.com/flameware/massive-design/issues/118)) are complete — 51 components. The P2 map closed the last **component-level** gap against shadcn/ui: eight built (Kbd, Input OTP, Resizable, Sidebar, Carousel, Chart 축소, Menubar, Navigation Menu), two absorbed as trigger modes of components we already had (Context Menu → Dropdown Menu, Hover Card → Popover), one ruled out for having no surface (Aspect Ratio). Their code and decisions live in `packages/`, `apps/storybook/`, `docs/tokens/`, and `docs/agents/figma-*.md`; [`docs/handoff/component-map.md`](docs/handoff/component-map.md) is the historical handoff into the completed component map.

Five rules from the P1, P2 and surface-gap maps bind later catalog work:

- **An item that derived channels cannot tell apart does not get its own component** ([#97](https://github.com/flameware/massive-design/issues/97)). Manifests and Figma carry anatomy and configuration state, not behaviour, so a behaviour-only variant cannot satisfy the "code, Storybook and Figma in one generation" completion definition. This is the rule that ruled Drawer out against Sheet, and it governs P2 triage.
- **A composed component consumes the original rather than copying it** ([#91](https://github.com/flameware/massive-design/issues/91)). Combobox imports Command and Popover; copying would fork their keyboard contracts.
- **A third-party library owns the nodes we do not give a `className` to, and the contract must say so** ([#122](https://github.com/flameware/massive-design/issues/122)). The boundary is class ownership; each externally-owned surface is listed in `externalSurfaces` with its own reason. Ownership reaches further than nodes — it takes inline styles ([#124](https://github.com/flameware/massive-design/issues/124)) and prop name spaces ([#125](https://github.com/flameware/massive-design/issues/125)) too. Its corollary: **we do not re-export a third-party component through our barrel**, because a surface cannot be ours and theirs at once.
- **A new axis's default is the value that preserves published instances** ([#139](https://github.com/flameware/massive-design/issues/139)'s four batches). `knockout: none`, `placement: auto`, `frame: none` (but `icon` for `EmptyMedia`, because that is what it already rendered), `spacing: separate`, `indicator: pill` — in every case the default is the value the part already rendered, which is what makes opening an axis `additive` rather than a reinterpretation of instances already published to Figma. "The default emits no class" is the wrong gloss and it misled: only three of the five emit `""`, while `frame` and `indicator` name a shape the part was already drawing. [#161](https://github.com/flameware/massive-design/issues/161) re-measured this and kept all five names — see the next rule.
- **An axis name must not already mean something else in the catalog** ([#125](https://github.com/flameware/massive-design/issues/125)). Upstream's name is the default choice, but only if it is free here. `align` was taken twice over — by recharts' `Legend` props and by Radix's floating-surface alignment — so the addon axis became `placement` ([#144](https://github.com/flameware/massive-design/issues/144)); `variant` already names the root's semantic/emphasis axis, so the media slot became `frame` ([#145](https://github.com/flameware/massive-design/issues/145)) and the tab marker became `indicator` ([#146](https://github.com/flameware/massive-design/issues/146)). Of the catalog's part-level axes, none is named `variant`. **Value names are the other way round: their name space is the axis, not the catalog** — `chart.indicator`'s `line` and `tabs.indicator`'s `line` mean different pictures and that is not a collision. And a value names the state of *what the axis names*, never whether a class is emitted: `frame: none` means no frame, not no class. So there is no shared name for a neutral default, and the five keep the five names they have ([ADR-0008](docs/adr/0008-axis-and-value-name-spaces.md), from [#161](https://github.com/flameware/massive-design/issues/161)). No gate sees this — it is a meaning judgement, and ADR-0006's rule against claiming what a gate cannot see applies.

The **표면 층위 공백 닫기** map ([#139](https://github.com/flameware/massive-design/issues/139)) has opened every promoted surface: Avatar's badge/group/count ([#143](https://github.com/flameware/massive-design/issues/143), which stood up `--ds-border-knockout` and [ADR-0007](docs/adr/0007-knockout-border.md)), `AlertAction` and the addon `placement` axis ([#144](https://github.com/flameware/massive-design/issues/144)), the `frame` axis shared by `ItemMedia` and `EmptyMedia` ([#145](https://github.com/flameware/massive-design/issues/145)), Toggle Group `spacing` and Tabs `indicator` ([#146](https://github.com/flameware/massive-design/issues/146)), and Dropdown Menu's six check/radio/submenu parts ([#142](https://github.com/flameware/massive-design/issues/142) adjudicated them, [#154](https://github.com/flameware/massive-design/issues/154) built them). Zero new tokens across all five generations. The cross-batch axis vocabulary closed with no rename ([#161](https://github.com/flameware/massive-design/issues/161), [ADR-0008](docs/adr/0008-axis-and-value-name-spaces.md)). One child remains open: the recheck that would let the map claim its destination ([#162](https://github.com/flameware/massive-design/issues/162)) — the map does not declare the gap closed until something measures it, because [#121](https://github.com/flameware/massive-design/issues/121)'s census already missed three surfaces once ([#127](https://github.com/flameware/massive-design/issues/127) found the hole).

Registering `parts` keeps uncovering gate violations that the missing field was hiding — `DropdownMenuSeparator` put `--ds-border-default` on `background-color` for 43 generations because its cell never reached a manifest. [#155](https://github.com/flameware/massive-design/issues/155) carries the remaining ten contracts in that state, and `select` has the same violation waiting ([#130](https://github.com/flameware/massive-design/issues/130)).

Open follow-ups, each large enough to want its own charting: the touch target size rule and the verification-runbook amendment it implies ([#111](https://github.com/flameware/massive-design/issues/111)), and the `--ds-bg-neutral-solid` alias gap ([#109](https://github.com/flameware/massive-design/issues/109)).

The P2 map left four open questions in its **Not yet specified** — the Base UI migration (our 24 primitives are all `radix-ui`; upstream leads with Base UI), the dependency weight `recharts` added, configuration-state modifiers landing as `unresolved` in manifests, and control gestures having neither automated checks nor a runbook hook. Figma's published baseline stands at 43 component sets (`verification/figma-baseline.json`) against 51 in code, and five more Repo verification generations have landed since — [#138](https://github.com/flameware/massive-design/issues/138) carries the target. Figma Sync runs only on an explicit request, in its own issue.

When updating code-derived Storybook or Figma channels, start with `bun run sync:preflight`, then follow `docs/agents/design-system-sync.md` for Figma and human checkpoints.
