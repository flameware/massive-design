## Where the work stands

The **토큰 파운데이션** map ([#1](https://github.com/flameware/massive-design/issues/1)), **컴포넌트 맵** ([#14](https://github.com/flameware/massive-design/issues/14)), **P0 카탈로그 확장 구현 맵** ([#78](https://github.com/flameware/massive-design/issues/78)), **P1 카탈로그 확장 구현 맵** ([#88](https://github.com/flameware/massive-design/issues/88)), and **P2 카탈로그 확장 구현 맵** ([#118](https://github.com/flameware/massive-design/issues/118)) are complete — 51 components. The P2 map closed the last **component-level** gap against shadcn/ui: eight built (Kbd, Input OTP, Resizable, Sidebar, Carousel, Chart 축소, Menubar, Navigation Menu), two absorbed as trigger modes of components we already had (Context Menu → Dropdown Menu, Hover Card → Popover), one ruled out for having no surface (Aspect Ratio). Their code and decisions live in `packages/`, `apps/storybook/`, `docs/tokens/`, and `docs/agents/figma-*.md`; [`docs/handoff/component-map.md`](docs/handoff/component-map.md) is the historical handoff into the completed component map.

Six rules from the P1, P2 and surface-gap maps bind later catalog work:

- **An item that derived channels cannot tell apart does not get its own component** ([#97](https://github.com/flameware/massive-design/issues/97)). Manifests and Figma carry anatomy and configuration state, not behaviour, so a behaviour-only variant cannot satisfy the "code, Storybook and Figma in one generation" completion definition. This is the rule that ruled Drawer out against Sheet, and it governs P2 triage.
- **A composed component consumes the original rather than copying it** ([#91](https://github.com/flameware/massive-design/issues/91)). Combobox imports Command and Popover; copying would fork their keyboard contracts.
- **A third-party library owns the nodes we do not give a `className` to, and the contract must say so** ([#122](https://github.com/flameware/massive-design/issues/122)). The boundary is class ownership; each externally-owned surface is listed in `externalSurfaces` with its own reason. Ownership reaches further than nodes — it takes inline styles ([#124](https://github.com/flameware/massive-design/issues/124)) and prop name spaces ([#125](https://github.com/flameware/massive-design/issues/125)) too. Its corollary: **we do not re-export a third-party component through our barrel**, because a surface cannot be ours and theirs at once.
- **A new axis's default is the value that preserves published instances** ([#139](https://github.com/flameware/massive-design/issues/139)'s four batches). `knockout: none`, `placement: auto`, `frame: none` (but `icon` for `EmptyMedia`, because that is what it already rendered), `spacing: separate`, `indicator: pill`, `rank: legend` — in every case the default is the value the part already rendered, which is what makes opening an axis `additive` rather than a reinterpretation of instances already published to Figma. "The default emits no class" is the wrong gloss and it misled: only three of the six emit `""`, while `frame`, `indicator` and `rank` name a shape the part was already drawing. `rank: legend` is the sharpest case ([#164](https://github.com/flameware/massive-design/issues/164)): upstream's `legend` is a *different* shape from ours, because upstream's value names a **role** and its declaration differs across all eight style branches — so we took the role and drew it at the scale our published instances already had. [#161](https://github.com/flameware/massive-design/issues/161) re-measured this and kept all five names — see the next rule.
- **An axis name must not already mean something else in the catalog** ([#125](https://github.com/flameware/massive-design/issues/125)). Upstream's name is the default choice, but only if it is free here. `align` was taken twice over — by recharts' `Legend` props and by Radix's floating-surface alignment — so the addon axis became `placement` ([#144](https://github.com/flameware/massive-design/issues/144)); `variant` already names the root's semantic/emphasis axis, so the media slot became `frame` ([#145](https://github.com/flameware/massive-design/issues/145)), the tab marker became `indicator` ([#146](https://github.com/flameware/massive-design/issues/146)), and the field caption's tier became `rank` ([#164](https://github.com/flameware/massive-design/issues/164)). No part-level axis *introduces* `variant` — `ToggleGroupItem.variant` is the root's own axis **inherited** onto the part ([#179](https://github.com/flameware/massive-design/issues/179)), which is the global name space working, not an exception to it. **Value names are the other way round: their name space is the axis, not the catalog** — `chart.indicator`'s `line` and `tabs.indicator`'s `line` mean different pictures and that is not a collision. And a value names the state of *what the axis names*, never whether a class is emitted: `frame: none` means no frame, not no class. So there is no shared name for a neutral default, and the five keep the five names they have ([ADR-0008](docs/adr/0008-axis-and-value-name-spaces.md), from [#161](https://github.com/flameware/massive-design/issues/161)). No gate sees this — it is a meaning judgement, and ADR-0006's rule against claiming what a gate cannot see applies.
- **A contrast requirement follows the role, not the token family** ([#109](https://github.com/flameware/massive-design/issues/109)). WCAG 1.4.11 binds "UI components that indicate state", so a *fill* can be inside the non-text gate: a **control affordance** — Scroll Area's thumb, Switch's off track — is the thing you grab, so it owes 3:1 against the surface it sits on and takes `bg.neutral.solid` (alias `neutral-solid`, [ADR-0003](docs/adr/0003-neutral-solid-alias-name.md)). Its opposite, the **track remainder** (Progress, Slider), owes nothing, because the filled part carries the meaning. Both roles are defined in `CONTEXT.md`. Four places had agreed on neutral 3 by accident, reached through three different paths (`bg-secondary`, `bg-muted`, and `--ds-state-base: var(--secondary)`); two of them were invisible at 1.09:1 and 1.17:1 and passed three gates in silence — `tokens:contrast` had no such pair, manifest lint rule 3 reads families and says so itself, and axe does not measure a custom scrollbar's affordance. `CODE_VERIFIED` is not a disproof of a defect no gate is looking for.

The **표면 층위 공백 닫기** map ([#139](https://github.com/flameware/massive-design/issues/139)) has now opened all eight promoted surfaces: Avatar's badge/group/count ([#143](https://github.com/flameware/massive-design/issues/143), which stood up `--ds-border-knockout` and [ADR-0007](docs/adr/0007-knockout-border.md)), `AlertAction` and the addon `placement` axis ([#144](https://github.com/flameware/massive-design/issues/144)), the `frame` axis shared by `ItemMedia` and `EmptyMedia` ([#145](https://github.com/flameware/massive-design/issues/145)), Toggle Group `spacing` and Tabs `indicator` ([#146](https://github.com/flameware/massive-design/issues/146)), Dropdown Menu's six check/radio/submenu parts ([#142](https://github.com/flameware/massive-design/issues/142) adjudicated them, [#154](https://github.com/flameware/massive-design/issues/154) built them), and `FieldLegend`'s `rank` axis ([#164](https://github.com/flameware/massive-design/issues/164)). Zero new tokens across all six generations. The cross-batch axis vocabulary closed with no rename ([#161](https://github.com/flameware/massive-design/issues/161), [ADR-0008](docs/adr/0008-axis-and-value-name-spaces.md)). **The eighth was found by a recheck, not by the map** ([#162](https://github.com/flameware/massive-design/issues/162)): Field was named in the destination's roster but never got an implementation ticket, so for five generations the map said it had opened eight when it had opened seven. That recheck also disproved the map's corollary — opening the whole roster does *not* leave the surface-level gap at zero — and named why: [#121](https://github.com/flameware/massive-design/issues/121)'s census took its population from a **table's diff column** rather than from an identifier set, so the unit of comparison was a row, not a name, and everything on a "no change" row fell out. Dropdown Menu ([#127](https://github.com/flameware/massive-design/issues/127)) was not an exception to that but its one noticed instance. The fix is a mechanical set difference between upstream's registry source and our `publicExports`/manifest `axes`, and per ADR-0006 it is **not** a gate — the procedure and its reproduction commands are the runbook [`docs/agents/upstream-surface-recount.md`](docs/agents/upstream-surface-recount.md) ([#176](https://github.com/flameware/massive-design/issues/176)), which every later upstream recheck starts from. The 15 surfaces it turned up across 9 components are a new population and go out as their own map.

The **파생 채널이 담지 못하는 계약** map ([#140](https://github.com/flameware/massive-design/issues/140)) is complete — nine tickets, `schemaVersion` 5 → 11, and modifier `unresolved` down from 145 `(component, property)` pairs to **10 keys / 17 cells, every one of them owned** (6 keys/9 cells are the map's own Out of scope, 4 keys/8 cells wait on [#155](https://github.com/flameware/massive-design/issues/155)). Four rules from it bind later work:

- **A grade of "not in this cell" is not one thing but four** ([#180](https://github.com/flameware/massive-design/issues/180), [ADR-0012](docs/adr/0012-drawn-elsewhere.md)). `unresolved` (not handled yet) · `ignore:` (never there) · `externalSurfaces` (not ours) · `elsewhere:` (there, not here). ② and ④ are split by **whether it is drawn**, ③ and ④ by **owner versus place**, and `elsewhere:` must name *where* that place is. Its corollary is the map's own method: when a signal mixes grades you cannot read what it points at, so the fix is always to add the grade, never to widen `ignore:`.
- **The policy table holds meanings; shape is peeled off before lookup, and a chain is a path** ([#178](https://github.com/flameware/massive-design/issues/178), [#182](https://github.com/flameware/massive-design/issues/182), [ADR-0014](docs/adr/0014-modifier-chains-are-paths.md)). A term binds the **subject** at that position and only a slot designator moves the subject, so order changes meaning only through subject movement (`[&_svg]:disabled` ≡ `svg:disabled`). Never widen the table to compound keys — it grows with the combinations and leaks at the next chain.
- **The contract bears the label, and the gate only ever checks the declaration for falsehood** ([#148](https://github.com/flameware/massive-design/issues/148), [#181](https://github.com/flameware/massive-design/issues/181), [#184](https://github.com/flameware/massive-design/issues/184), [ADR-0009](docs/adr/0009-drawn-but-not-carried.md), [ADR-0013](docs/adr/0013-slot-labels-are-borne-by-the-contract.md)). `drawnBy` says what draws each configuration state and `slots` names a designated descendant — except where **the selector states the role itself** (`[&_svg]` means "an icon anywhere"), which is the one line on the other side. Where a hand-written sentence could diverge from the policy table, the gate asks the table back rather than trusting a copy.
- **What derived channels do not carry, the contract declares and a person verifies — and the boundary is the cause** ([#149](https://github.com/flameware/massive-design/issues/149), [#187](https://github.com/flameware/massive-design/issues/187), [ADR-0010](docs/adr/0010-behaviors-are-declared-and-human-verified.md), [ADR-0015](docs/adr/0015-behaviors-boundary-is-the-cause.md)). `behaviors` takes interactions whose cause is **not an explicit activation** (hover, drag, long press, a timer, focus arriving, typing at a *closed* control) in three kinds — `control-gesture`, `open-cause`, `implicit-change`. It does not take what the role already requires (arrow movement and highlighting inside an open surface, Escape and outside-press dismissal, click activation, and the defaults hanging off those: `loop`, `modal`, focus trap, scroll lock), nor changes a person did not cause (image load, password-manager detection, container resize). All 51 contracts were surveyed against the sources `bun.lock` pins — **not the docs, which do not tell you the version we installed** — so `behaviors: {}` now means "confirmed it brings nothing". `bun run sync:checklist` prints the human checklist from the contracts; a list kept by hand leaked three times.

Two facts that survey turned up outlive it. **`activationMode` ships as `"automatic"`** — arrow keys move the Tabs panel on focus alone, and this contract's prose had been reasoning from `manual` for generations. **Scroll Area's scrollbar is gated on hover** (`type="hover"`, hidden 600ms after the pointer leaves) while the manifest publishes its `ScrollBar` cell and every static comp draws it always-visible — the first case where a derived channel carries a surface whose *existence* is conditional on an interaction.

The map closes with fog it did not chart, and it belongs to later generations, not to a resumption of this one: how Figma draws the `configurations` [#148](https://github.com/flameware/massive-design/issues/148) put in the cells (VARIANT would multiply the set, so it carries the weight of [#24](https://github.com/flameware/massive-design/issues/24)); the declarations that must flip the moment [#155](https://github.com/flameware/massive-design/issues/155) registers parts (four `drawnBy` reasons and `switch`'s 4 keys/8 cells — count how many verdicts that generation overturns *before* running it); whether a cell without a state ladder loses its `disabled` opacity by decision or by omission; and `literal` passing values it cannot actually resolve (runtime CSS variables, and Tailwind's own composed `--tw-*` chains — 13 keys/23 cells, the same shape as the `--tw-shadow` unwrap that already exists).

Registering `parts` keeps uncovering gate violations that the missing field was hiding — `DropdownMenuSeparator` put `--ds-border-default` on `background-color` for 43 generations because its cell never reached a manifest. [#155](https://github.com/flameware/massive-design/issues/155) carries the remaining ten contracts in that state, and `select` has the same violation waiting ([#130](https://github.com/flameware/massive-design/issues/130)).

One open follow-up is large enough to want its own charting: the touch target size rule and the verification-runbook amendment it implies ([#111](https://github.com/flameware/massive-design/issues/111)). The `--ds-bg-neutral-solid` alias gap ([#109](https://github.com/flameware/massive-design/issues/109)) is closed — it turned out to be a role split, not a missing name, and is the sixth rule above.

The **primitive·의존성 기반 확정** map ([#141](https://github.com/flameware/massive-design/issues/141)) is complete — four tickets, two ADRs, and **no code change at all**, which is what it set out to be: the owner made it planning-only, so its deliverable is a decision and the ground later compatibility arguments stand on. Two rules come out of it:

- **The base is one, and the burden of proof is on whoever changes it** ([#152](https://github.com/flameware/massive-design/issues/152), [ADR-0016](docs/adr/0016-primitive-base-stays-radix.md)). primitive stays `radix-ui`; "upstream leads with it" is not by itself a reason, which is [#118](https://github.com/flameware/massive-design/issues/118)'s rule 2 applied to the base itself. Counted from documentation, migration gains **one** confirmed thing (Base UI's `render` is a superset of `asChild`) against **three** losses (Accordion's roving focus removed, Tabs' `activateOnFocus` defaulting to manual against our shipped `automatic`, no standalone `Label`) — 23 of 24 components move grade for that. The shape is a **conditional stay with four event-based triggers**, never a date, because a date measures nothing. It binds **new** components too: a base that splits, splits by accident, not by judgement. The evidence grade is documentation-only, so re-adjudication carries [#150](https://github.com/flameware/massive-design/issues/150) §10's 23 unconfirmed items as a precondition — installed against the real thing.
- **A dependency's weight is a floor cost, not a property of the library** ([#153](https://github.com/flameware/massive-design/issues/153), [ADR-0017](docs/adr/0017-dependency-weight-is-a-floor-cost.md)). The floor cost is what a consumer pays importing **zero** components. There is no single number to hang on a library — the same `recharts` is 8,371 B for `ResponsiveContainer` alone and 407,702 B through the chart body — so a library-screening gate claims what a gate cannot see (ADR-0006). Install counts pointed the opposite way: the two packages with **zero** exclusive dependencies are the polluters, and the one with 37 adds nothing. What raises the floor is **packaging, not dependency choice** — an undeclared `sideEffects` — so the remedy is a declaration, never ripping the library out, and pricing accessibility behaviour by line count is exactly what [ADR-0016](docs/adr/0016-primitive-base-stays-radix.md) just refused. `bun.lock` is the authority for reproducibility; `package.json`'s pin-or-range is re-read as an intent to follow that library's minors, which is why only the base is a range.

Two things that map turned up outlive it. **`@massive/ui` declares no `sideEffects` itself** — we were in the state we were about to fault others for, and `["*.css"]` is the accurate declaration. And **`react-is` is a runtime peer no workspace package declares**, satisfied by accident through `storybook → @testing-library/dom → pretty-format`; blocking it fails even the smallest build, so every check passing meant a dev dependency was quietly covering, and that cover does not exist outside the repo. Both fixes are packaging, move no contract or manifest hash, and go out as their own effort — as does the automated floor-cost gate, which waits on measuring whether Vite/Rollup/webpack judge an undeclared `sideEffects` the way bun does; committing a baseline before that would have the gate manufacture the very silence it exists to catch.

The P2 map's four open questions are now two. **[#140](https://github.com/flameware/massive-design/issues/140) closed the other two** — configuration-state modifiers landing as `unresolved`, and control gestures having neither automated checks nor a runbook hook. Both of those — the Base UI migration and the dependency weight `recharts` added — are now closed by [#141](https://github.com/flameware/massive-design/issues/141) above, in each case as a decision rather than a change. Figma's published baseline stands at 43 component sets (`verification/figma-baseline.json`) against 51 in code, and five more Repo verification generations have landed since — [#138](https://github.com/flameware/massive-design/issues/138) carries the target. Figma Sync runs only on an explicit request, in its own issue.

When updating code-derived Storybook or Figma channels, start with `bun run sync:preflight`, then `bun run sync:checklist` for the human behaviour checks the contracts declare, then follow `docs/agents/design-system-sync.md` for Figma and human checkpoints.
